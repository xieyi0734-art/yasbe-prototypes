★ 三项决策对集成的影响
决策 1 · 实时筛查

需设计 「筛查中」等待态（1-3 秒），建议 loading 动画 + 超时兜底。

开户表单提交后同步阻塞，需评估接口耗时对转化率影响；高并发需关注限流（默认 300 次/分）。

决策 2 · 自建案件系统

开发量最大：告警拉取、风险详情渲染、决策回写 三块全自研。

建议：案件列表 + 审核详情页 + 决策按钮（通过/拒绝）+ 审计日志，四个模块 MVP。

审核人员流程：待办列表 → 查看告警 → 决策 → 自动回写。

决策 3 · 持续监控

成本随客户数线性增长（每客户每 24h 一次筛查）。

建议先全开观察命中率，再按风险分层优化：低风险可降频，静音规则过滤噪音告警，减少人工工作量。

✓ 对接前仍需确认的内容
商务 / 合同
  • 计费模型：按筛查次数 / 订阅制 / 批量折扣？（问 account manager）
  • 区域实例：EU / US / CA / AU 六区选哪个（数据驻留 + webhook 来源 IP）
  • 持续监控费率确认（决策 3 已开，成本项必问）
合规 / 配置
  • 筛查配置：KYC 个人 vs KYB 企业是否用不同名单组合？
  • 风险分公式：属性权重、阈值 → 低/中/高/禁止（合规团队定）
  • PEP 分级 CLASS 1-4 策略：一票否决 or 加权计分
  • 负面媒体 12+ 子类：哪些直接拒、哪些进人工
  • PROHIBITED 自动拒绝是否开启
技术 / 集成
  • external_identifier 唯一映射我方客户 ID（重复 409）
  • customer_identifier 创建后必须存库（案件系统主键）
  • token 24h 过期，建议 23h 自动刷新
  • webhook at-least-once：按 webhook-id 去重 + 签名校验
  • 429 退避重试、500 最多重试 3 次
  • 测试用例：Test CleanUser → 未命中；Victor Bout → 命中
产品 / 体验
  • 「筛查中」等待态设计（1-3 秒 loading + 超时兜底）
  • 命中客户前台显示「审核中」而非直接拒绝
  • 审核系统：待办列表 / 详情 / 决策按钮 / 审计日志
  • 风控复审 SLA：谁看案件？多久必须处理？超时自动策略？
  • 客户改地址/国籍 → 重算分 → 升档再筛查的提示
  • 关户即停监控（省钱），历史案件保留
