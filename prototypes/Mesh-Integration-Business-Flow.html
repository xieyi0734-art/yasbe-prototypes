★ 三个必须先拍板的产品决策
决策 1 · 入驻实时 or 异步？

同步 = 开户表单提交后卡 1-3 秒实时拿结果，可立即放行/拦截，体验好。

异步 = 先收单后筛查，走风控复审流程。

文档推荐实时场景用 同步 + last_sync_step=ALERTING（一次调用拿全结果）。

决策 2 · 案件评审放哪？

Mesh 网页版：零开发，运营去对方后台操作，只接一个 webhook 收结果。

自有案件系统：实现告警拉取、风险详情、决策回写，工作量差 3-5 倍。

这是影响集成成本最大的分叉点。

决策 3 · 持续监控开不开？

开启 = 每个客户每 24h 重筛查，新命中自动出案件，合规价值高，但 按筛查量计费，成本随客户数线性涨。

建议：高风险客户开、低风险关，或全开配静音规则减噪音。

✓ 对接前需要了解的内容清单
商务 / 合同
  • 计费模型：按筛查次数 / 订阅制 / 批量折扣？（文档未公开，问 account manager）
  • 区域实例：EU / US / CA / AU 六区选哪个（数据驻留 + webhook 来源 IP）
  • 默认限流 300 次/分钟，可申请调整
  • webhook 签名按账号开启（opt-in），密钥轮换走人工支持
合规 / 配置
  • 筛查配置：个人 vs 公司是否用不同名单组合？国家分级？
  • 风险分公式：属性权重、阈值 → 低/中/高/禁止（合规团队参与）
  • PEP 分级 CLASS 1-4：一票否决 or 加权计分
  • 负面媒体 12+ 子类：哪些直接拒、哪些进人工
  • PROHIBITED 是否自动离船
技术 / 集成
  • external_identifier 唯一映射我方客户 ID（重复 409）
  • customer_identifier 创建后必须存库
  • token 24h 过期，建议 23h 自动刷新
  • webhook at-least-once 需按 webhook-id 去重 + 签名校验
  • 429 退避重试、500 最多重试 3 次
  • 测试用例：Test CleanUser → 未命中；Victor Bout → 命中
产品 / 体验
  • 同步模式「筛查中」等待态设计（1-3 秒）
  • 命中客户前台显示「审核中」而非直接拒
  • 风控复审 SLA：谁看案件？超时自动策略？
  • 客户改地址/国籍 → 触发重算分，可能升档再筛查
  • 关户即停监控（省钱），历史案件保留
