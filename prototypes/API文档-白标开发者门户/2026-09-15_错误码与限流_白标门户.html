错误码与限流

错误响应结构固定，业务错误永远带一个稳定的 code —— 请按 code 分支，不要解析 message（文案可能调整）。

错误响应结构

JSON复制
{
  "error": {
    "code": "insufficient_funds",
    "message": "Source account balance is not sufficient for this payout",
    "param": "source_account_id",
    "details": [
      {"field": "amount", "issue": "exceeds_available_balance"}
    ],
    "request_id": "req_6c19b0a4",
    "doc_url": "https://docs.yasbee.com/errors#insufficient_funds"
  }
}

把 request_id 打进你的日志。联系我们时提供它，我们能直接定位到请求与通道回执。

HTTP 状态语义

状态码含义典型场景 / 应对
200成功注意：HTTP 200 不代表业务终态成功，看对象的 status
400请求格式错误JSON 语法问题、类型不符 —— 改代码
401未认证密钥缺失 / 失效 / 环境用错（test 密钥打生产）
403无权限scope 不足、IP 不在白名单、风控拦截（如 risk_level_exceeded）
404资源不存在ID 拼错；或调了 /v1/sandbox/* 但用的是生产密钥
409冲突幂等键复用但请求体不同、重复主体
422业务校验失败最常见：余额不足、同名校验不通过、报价过期 —— 需业务处理
429触发限流按 Retry-After 退避重试，不要立即重放
500 / 503平台异常 / 不可用可重试（带幂等键），指数退避；连续失败请联系对接人

幂等语义

场景行为
同一 Idempotency-Key + 相同请求体返回首次的响应（含相同资源 ID），不重复创建
同一 Idempotency-Key + 不同请求体409 idempotency_key_reuse
未带 Idempotency-Key 的写请求允许，但超时重试可能产生重复 —— 不推荐
键的有效期24 小时。同一键在有效期内始终返回首次结果

限流

限流按密钥 + 端点组维度计算，滑动窗口。响应头会告诉你当前状态，不要靠猜测。

端点组沙盒生产说明
查询类（GET）20 req/s按合同列表、详情、余额
写操作（客户 / 账户）5 req/s按合同创建、更新
资金类（出款 / 兑换 / 提现）2 req/s按合同单笔上限另见走廊限制
批量出款1 req / 10s按合同单批条数另有限制
报价类10 req/s按合同用于批量试算时请节流
沙盒模拟端点5 req/s—仅沙盒

沙盒配额可在门户查看，用于防止误压测；生产配额在合同中约定，如需提升联系我们。

限流响应头

HTTP复制
HTTP/1.1 429 Too Many Requests
X-RateLimit-Limit: 5
X-RateLimit-Remaining: 0
X-RateLimit-Reset: 17435          # 距窗口重置的秒数
Retry-After: 1

{ "error": { "code": "rate_limited", "message": "Too many requests" } }

重试策略

✅

可以重试

429（按 Retry-After）、500 / 503、网络超时。必须带同一 Idempotency-Key，指数退避 + 抖动。

⛔

不要重试

400 / 401 / 403 / 404 / 422。这些是代码或数据问题，重试只会重复失败并触发限流。

🔍
排错顺序 ① 看 error.code 与 details[] → ② 查本文档对应行 → ③ 在沙盒用模拟端点复现 → ④ 仍不明确就带 request_id 找对接人。跳过前三步直接问，通常要来回两轮。
