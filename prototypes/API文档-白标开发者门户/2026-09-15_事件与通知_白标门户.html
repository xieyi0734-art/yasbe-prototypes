事件与通知

状态变更通过 Webhook 主动推给你 —— 不要轮询。但也不要只依赖 Webhook： 事件可能重复、乱序或延迟，正确姿势是「事件驱动 UI + 定时查询兜底」。

事件对象

JSON复制
{
  "id": "evt_1f8a90c3d7",
  "type": "payout.completed",
  "created_at": "2026-09-15T08:52:07.221Z",
  "environment": "sandbox",
  "data": {
    "object": "payout",
    "id": "pay_9d3b7710e2",
    "status": "completed",
    "customer_id": "cus_3f81a2bc9d",
    "amount": "1250.00",
    "currency": "USD",
    "target_amount": "8951.20",
    "target_currency": "CNY"
  },
  "request_id": "req_6c19b0a4"
}

data 只带摘要字段。收到事件后如需完整对象，用 data.id 回查对应端点 —— 这是最稳的实现方式。

投递与重试

投递方式
POST JSON 到你在门户配置的 HTTPS 端点；请求头含 X-YASBe-Signature 与 X-YASBe-Event-Id
成功判定
HTTP 2xx 视为成功。其它状态码一律视为失败并重试
重试策略
指数退避，最多 8 次、最长 24 小时；之后进入「待重投」状态，可在门户手动重投
超时
单次投递 10 秒未响应即判失败 —— 你的端点应先落库快速返回 200，再异步处理
顺序
不保证顺序。请以事件里的对象状态为准，而不是到达顺序
重复
可能重复投递。用 event.id 做幂等键去重

签名校验

签名头格式 t=<时间戳>,v1=<签名>，签名 = HMAC-SHA256(t + "." + 原始请求体, 你的端点密钥)。请用原始 body 校验，不要用反序列化后再序列化的内容。

NodePython复制
const crypto = require('crypto');

function verify(rawBody, signatureHeader, secret) {
  const parts = Object.fromEntries(
    signatureHeader.split(',').map(p => p.split('='))
  );
  const expected = crypto
    .createHmac('sha256', secret)
    .update(parts.t + '.' + rawBody)
    .digest('hex');

  // 防重放：超过 5 分钟视为过期
  if (Math.abs(Date.now() / 1000 - Number(parts.t)) > 300) return false;
  return crypto.timingSafeEqual(Buffer.from(expected), Buffer.from(parts.v1));
}
import hmac, hashlib, time

def verify(raw_body: bytes, signature_header: str, secret: str) -> bool:
    parts = dict(p.split('=') for p in signature_header.split(','))
    expected = hmac.new(
        secret.encode(), f"{parts['t']}.".encode() + raw_body, hashlib.sha256
    ).hexdigest()

    if abs(time.time() - int(parts['t'])) > 300:   # 防重放
        return False
    return hmac.compare_digest(expected, parts['v1'])
⚠️
端点密钥可在门户重置重置后旧签名立即失效。若你需要灰度轮换，可以同时保留两个密钥一段时间（门户支持双密钥并存）。

沙盒里的 Webhook

  • 沙盒会真实投递事件（与生产同一套投递与签名机制），因此验签逻辑可以在沙盒完整验证。
  • 手动重投 —— POST /v1/sandbox/webhook-events/{id}/redeliver，或在门户「请求日志」里点重投，用于测试幂等。
  • 本地开发 —— 沙盒允许 http:// 回调地址，方便用内网穿透工具；生产必须 HTTPS。
  • 投递记录 —— 门户里可查看每次投递的状态码、耗时与响应体片段，排查看这里最快。

实现要点

  • 端点在 500ms 内返回 2xx：先写消息队列/落库，异步再处理业务。
  • 用 event.id 幂等；不要用 data.id（同一对象会有多个事件）。
  • 不要假设事件一定到达 —— 用「未终态交易定时轮询」兜底，两小时一次足够。
  • 不要按到达顺序覆盖状态 —— 用事件里的 status 与本地状态机的单向推进规则判断。
  • 回调端点不要做重活，也不要调用我们的 API 等待响应（会放大故障）。
