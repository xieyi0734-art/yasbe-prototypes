沙盒环境

沙盒是一个与你生产数据完全隔离的环境，用来把集成链路跑通： 合同没签、KYB 没过也能开始；秒级自助开通，不需要发邮件申请。

🧪
沙盒不会产生真实资金 通道行为、清算时效、真实风控结果都不在沙盒里发生。沙盒保证的是请求/响应结构、状态机与错误码一致。

自助开通

不需要 KYB、不需要对接人审批。开通后会自动为你预置一套测试主体与测试数据，可以直接开始调用。

进入门户 · 开发者设置

登录 portal.yasbee.com，打开 开发者设置 → 环境。

点击「开通沙盒环境」

系统为你分配独立的沙盒租户（sbx_...），与其它白标客户、与你的生产租户三方隔离。

创建沙盒密钥

生成 sk_test_ 前缀密钥。沙盒密钥可创建多个（按团队/服务拆），也可以只读；默认不限制 IP，方便本地联调。

开始调用

把基址换成 https://api-sandbox.yasbee.com/v1，其余代码不用改。建议第一件事是跑通 创建客户 + 模拟 KYB 通过。

ℹ️
沙盒也会限流 沙盒的配额低于生产，用于防止滥用；压测请在沙盒做但不保证 SLA。 具体数值见 错误码与限流。

环境与密钥

Sandbox
https://api-sandbox.yasbee.com/v1
  • 密钥前缀 sk_test_ / cli_test_
  • 自助创建，数量不限
  • 可调用 /v1/sandbox/* 模拟端点
  • IP 白名单可选
  • 数据 30 天滚动清理
VS
Live
https://api.yasbee.com/v1
  • 密钥前缀 sk_live_ / cli_live_
  • KYB 通过后由运营开通
  • 无模拟端点，请求即真实业务
  • IP 白名单必填
  • 数据长期保留，可导出对账单
⚠️
环境靠密钥区分，不靠请求头 你不需要（也不应该）在代码里写 if (sandbox) 分支：同一段代码配不同密钥就切换了环境。 但请把密钥放在配置中心，不要把 sk_test_ 硬编码进仓库。

模拟端点

真实世界的动作（通道到账、卡片被刷、链上确认、人工审批）在沙盒里不会自动发生，需要你主动触发。 所有模拟端点都在 /v1/sandbox/* 下，仅沙盒可用，生产调用返回 404。

方法模拟端点用途触发事件
SIM /v1/sandbox/customers/{id}/simulate_kyb_approval 把客户 KYB 置为通过，解锁账户、收款与开卡 customer.kyb_approved
SIM /v1/sandbox/customers/{id}/simulate_kyb_rejection 测试拒绝分支与补件流程（可指定原因码） customer.kyb_rejected
SIM /v1/sandbox/virtual-accounts/{id}/simulate_deposit 模拟一笔本地收款到账；可指定金额与付款方名称以测试同名 / 非同名分支 deposit.completed
deposit.pending_review
SIM /v1/sandbox/payouts/{id}/simulate_status 把出款从 processing 推进到 completed / failed / returned payout.*
SIM /v1/sandbox/cards/{id}/simulate_authorization 模拟一笔消费授权：商户名、MCC、金额、币种、是否 3DS，用于验证限额与 MCC 拦截策略 card.authorization_requested
card.authorization_declined
SIM /v1/sandbox/cards/{id}/simulate_settlement 把授权转为清算入账，形成卡交易流水 card.transaction_settled
SIM /v1/sandbox/crypto/simulate_deposit 模拟链上充值：指定资产、链、金额与确认数，可停在「确认中」以测试入账前状态 crypto.deposit_detected
crypto.deposit_confirmed
SIM /v1/sandbox/crypto/simulate_risk_scan 给指定地址设定扫描结果（risk_level 0–5），用于验证你的提示与拦截分支 —
SIM /v1/sandbox/webhook-events/{id}/redeliver 重投某个事件，验证你的验签与幂等逻辑 原事件重投
SIM /v1/sandbox/test-clock 时间旅行：把沙盒时间推到 T+1 / T+3，用于触发结算周期、报价过期、挂账自动退回等依赖时间的逻辑 settlement.generated 等
SIM /v1/sandbox/reset 清空沙盒业务数据（密钥与配置保留），回到干净状态重新跑回归 —

示例：模拟一笔非同名收款，验证挂账分支

cURL复制
curl -X POST https://api-sandbox.yasbee.com/v1/sandbox/virtual-accounts/va_7c29d10af5/simulate_deposit \
  -H "Authorization: Bearer sk_test_9f2c…" \
  -d '{
    "amount": "8000.00",
    "currency": "USD",
    "payer_name": "Sunrise Trade HK Ltd",   // 故意与账户名不同
    "reference": "VA-7C29D10AF5"
  }'

# 账户名为 Shanghai Sunrise Trading Co., Ltd. → 判定 mismatched
# 200 OK
{
  "transaction_id": "tx_9a10ff42c8",
  "status": "pending",
  "payer_name_match": "mismatched",
  "review_reason": "payer_name_mismatch",
  "auto_return_at": "2026-09-22T08:00:00.000Z"   // 7 天未处理自动退回
}

场景测试付款信息预期结果

测试钱包地址（加密风险闸门）

测试地址标签预置 risk_level预期结果
SBX-ADDR-CLEAN-011放行（0–2 均放行）
SBX-ADDR-WATCH-023拦截，触发 crypto.withdrawal.blocked
SBX-ADDR-SANCTION-035拦截，命中制裁类别

沙盒里的风险结果是你能自己设定的（simulate_risk_scan），用于穷举 0–5 全部分支；生产环境由平台的风控供应商实时判定，白标侧不可干预。

ℹ️
汇率在沙盒里是固定快照 报价结果取沙盒快照值、不随市场波动，因此你的金额断言可以写死。生产环境报价按实时市场生成，同一笔请求两次结果可能不同。

与生产的差异

这一节请务必读完再决定「沙盒通了就算通了」。

维度沙盒生产
资金无真实资金流转真实资金、真实扣款
请求 / 响应结构一致 —— 同一套契约，字段、校验、错误码相同
状态机一致 —— 状态枚举与推进顺序相同
通道行为全部为模拟，无真实通道接入真实本地清算 / 卡组织 / 链上网络
时效你触发才走，秒级受通道窗口影响，分钟到数天
风控结果由你设定平台风控供应商实时判定，≤2 放行、≥3 拦截
实名 / 合规审核用模拟端点直接给结果真实人工审核，需补件与沟通
数据保留30 天滚动清理长期保留
限流较低配额（防滥用）按合同约定
可用能力/v1/sandbox/* 可用/v1/sandbox/* 返回 404
⚠️
沙盒验证不了的三件事 ① 通道时效与失败率；② 真实风控命中后的运营流程；③ 生产环境的人工审核与补件体验。 这三件事建议在小金额生产灰度阶段验证，而不是指望沙盒。

上线检查清单

对接完成后逐项确认。这份清单也是我们上线评审时会一起过的东西。

✓
密钥未出现在前端与仓库App / 浏览器 / 公开仓库中不存在 sk_ 前缀字符串；密钥来自配置中心或环境变量。
✓
所有写请求带 Idempotency-Key出款、开卡、充值等资金类请求可重放而不产生重复。
✓
Webhook 验签 + 幂等落库重复投递与乱序到达都不会导致状态错乱。
✓
有主动查询兜底对账不依赖 Webhook 100% 到达；定时任务拉取未终态交易并修正。
✓
金额全部按字符串处理链路上没有浮点运算；前端展示与后端金额来源一致。
✓
非同名挂账有运营处理路径你能看到挂账列表、能触发上传证明 / 放行 / 退回。
✓
风险拦截有面向用户的文案地址被拦截时提示「更换地址」，而不是「请重试」。
✓
错误码已全部映射至少覆盖 错误码与限流 页列出的全部业务错误，含用户可读文案。
✓
生产密钥 + IP 白名单已配置生产密钥只授予必要的 scope，白名单为你的出口 IP。
✓
已跑通一笔小额真实业务生产环境小额收款或出款端到端成功，对账一致。

常见问题

沙盒需要 KYB 吗
不需要。开通沙盒是自助的，KYB 只影响生产密钥发放。
沙盒能用真实卡号 / 地址吗
不要。沙盒只接受测试数据；真实数据请只在生产使用，避免合规风险。
沙盒数据会保留多久
30 天滚动清理，需要长期保留的断言请在本地记录。
沙盒能压测吗
可以但不保证稳定性与配额；性能与容量请在生产灰度阶段评估。
沙盒 Webhook 能重投吗
可以，用 /v1/sandbox/webhook-events/{id}/redeliver，也可在门户的请求日志里点重投。
生产出现问题怎么排查
带上响应里的 request_id 联系对接人，我们可定位到具体请求与通道回执。
