端点路径为设计稿，最终以 API 契约为准。标 只读 的能力表示白标侧只能查询，不能改状态。

主体与账户

两层主体：你（白标主体）与你的终端客户。白标主体需要过 KYB； 终端客户是个人还是企业、需不需要 KYC，取决于你的业务场景和集成模式。

对象说明关键字段
customer终端客户，可为企业或个人。是所有资金动作的归属主体。type kyb_status kyc_status
account客户在某一币种下的账户，承载余额。同一客户可开多币种账户。currency available held
cardholder卡片模块的持卡人，与 customer 可一一对应，也可一对多。customer_id kyc_status
ℹ️
一个 KYB 下可以有 N 个持卡人企业客户申请多张卡不需要重复 KYB，只需为每个使用人建立持卡人并各自过 KYC。这条规则直接影响你的产品设计：企业卡池场景下「一个客户 → 多张卡」是原生支持的。

本地收款

给客户开立一个命名虚拟账户（名字挂客户、账号由平台分配），用本地实时清算通道收款 —— 资金到账即入账，不必等跨境链路。这是白标最容易变现的能力之一。

  • 开立 —— 指定客户、币种与通道国家，返回本地账号信息（含收款人名），可直接印在发票上。
  • 入账 —— 收到款后生成 transaction，状态从 pending 走向 completed。
  • 同名判定 —— 付款方名称与账户名比对：大小写、空格不敏感。同名自动入账；非同名默认挂账，需你上传证明或由运营审核后放行。
  • 挂账处理 —— 非同名款项挂账后 7 天内未处理，按规则自动退回原付款方。
⚠️
非同名不是异常，是常态终端用户经常用第三方代付。你的产品需要为「挂账」设计一个运营处理界面，否则钱到不了账、客户会来投诉。接口会通过 deposit.pending_review 事件通知你。

跨境出款

把余额付到收款人的本地银行账户，支持单笔与批量。流程固定为「登记收款人 → 拿报价 → 发起出款 → 等终态」。

步骤端点要点
登记收款人POST /v1/beneficiaries需按收款国家提交本地清算字段；返回后建议调用核验端点确认户名。
报价POST /v1/quotes返回汇率、手续费、到账金额与报价有效期；过期需重新取价。
发起出款POST /v1/payouts必须带 Idempotency-Key；出款方仅可选同名且账户状态正常的收款人。
批量POST /v1/payouts/batch单批上限按合同约定；逐条返回受理结果，不做整批回滚。
撤回POST /v1/payouts/{id}/recall仅在终态前可尝试；通道已清算则只能依赖退回流程。
🔁
出款是最容易出资金的环节建议实现三件事：发起前本地预校验（余额 + 同名 + 限额）、强制带幂等键、出款状态全部以 Webhook 为准并做落库对账。

兑换与稳定币桥

多币种兑换既可作为独立能力（客户自己换汇），也可作为跨境腿的中间环节（收款币种 → 出款币种）。

💱

法币 ↔ 法币

取报价 → 锁价 → 兑换。报价有效期短，锁价成功后按锁定价成交，滑点不落在你这边。

🪙

法币 ↔ 稳定币

把跨境腿换成稳定币结算，规避本地清算窗口与代理行延迟；链上到账后可按需再换回法币。

桥接能力是否需要单独开通、可用币对与单笔上限，取决于你的白标主体资质与通道覆盖，签约时确认。

卡片发行

从持卡人到卡片再到交易，全链路 API 化。白标客户的典型形态是「企业卡池」：一个企业客户为自己的员工或业务场景发多张卡。

创建持卡人

提交姓名、证件、地址等 KYC 信息，得到 chl_...。持卡人必须挂在某个 customer 下。

开卡

选卡种（虚拟 / 实体）、币种与额度，扣开卡费后生成卡片。实体卡需再提交收件信息进入制卡发货流程。

激活与充值

虚拟卡开卡即可用；实体卡需激活并设置 PIN。充值从客户余额扣款并计手续费。

交易与授权

消费产生授权与清算两条记录；可通过实时授权接口做自定义拦截（限额、MCC、商户维度）。

能力端点说明
卡片状态管理POST /v1/cards/{id}/freeze · /unfreeze · /close冻结即时生效
限额豁免申请POST /v1/cards/{id}/limit-exemptions提交后进入人工审核
实时授权决策POST /v1/cards/authorization-webhook（你暴露，我们回调）超时视为放行，需谨慎

加密钱包与出入金

加密侧的能力边界很清楚：我们做托管钱包 + 出入金 + 风险扫描，不做交易所撮合、不做自营做市。

能力端点风控口径
充值地址 POST /v1/crypto/deposit-addresses 按客户 + 资产 + 链生成专属地址
提现 POST /v1/crypto/withdrawals 出金需二次验证（TOTP）；外部地址先过风险扫描
归集 POST /v1/crypto/collections 按主体维度批量归集到热/冷钱包
地址风险扫描 GET /v1/crypto/risk-scans/{id} 只扫对方钱包地址；risk_level 0–2 放行、≥3 拦截
⛔
风险等级 ≥ 3 直接拦截，不可覆盖 扫描结果为 3（Medium）及以上时，提现请求会被拒绝且不能由白标侧强制放行。0–2 正常放行； 你可以在自己的产品里做更严格的加严策略，但不能放松平台的这条底线。白标侧可通过 crypto.withdrawal.blocked 事件拿到拦截原因并提示终端用户更换地址。

合规与风控

🪪

KYB / KYC

提交资料、查询结果、接收审批回调。结果分 approved / pending / rejected，拒绝时带可展示给用户的原因码。

🔍

名单筛查

制裁、PEP、负面舆情。企业主体额外做 UBO 穿透筛查。

📡

交易监控

法币交易按规则引擎监控；加密侧做地址级风险扫描。命中后进入人工案件。

ℹ️
合规责任按模式划分模式 A / C 下，终端客户的 KYC 与案件处置由 YASBe 承担，你只需保证提交信息真实；模式 B 下你会拿到完整的案件处置接口与责任。别在这一层想「能不能省掉」—— 上线后被要求补做的成本远高于一开始就做。

结算与对账

白标生意的最后一步是分润。平台的结算口径固定：按周期锁定 → 汇总明细 → 计算返佣 → 出结算单 → 你确认 → 划拨。

环节接口 / 产出周期
费用明细GET /v1/settlements/{id}/line-items实时可查
结算单GET /v1/settlements按合同（周 / 月）
对账单导出POST /v1/statements/export按日 / 按月
结算确认POST /v1/settlements/{id}/confirm异议期内

费率结构（开卡费、充值费率、出款费、FX 加点、分润比例）在合同中约定，不在 API 里配置；API 只返回实际发生的费用明细。

能力边界

写清楚「不做什么」，比列出一堆能力更能节省双方时间。

能力状态说明
本地收款 / 出款通道按走廊仅覆盖已开通走廊的国家与币种，清单随合同附件给到并按季度更新。
实体卡按地区制卡与邮寄存在区域限制，部分国家仅支持虚拟卡。
稳定币发行不支持平台不提供自营稳定币发行与收益类产品。
加密现货撮合不支持不提供交易所撮合、杠杆、衍生品；仅做托管钱包与出入金。
持牌业务代持不支持平台不代持你的牌照责任；模式 B 下你自己承担合规主体责任。
