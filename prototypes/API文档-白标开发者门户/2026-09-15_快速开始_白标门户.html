文档/快速开始

快速开始

四步完成第一次成功调用。沙盒环境无需 KYB、秒级开通，你可以先用沙盒把链路跑通， 再回来补生产资质。

⚡
只想先跑通一次请求？ 如果你已经签约并拿到沙盒密钥，可以直接跳到 第 4 步。 还没有密钥的话，沙盒环境 里有自助开通入口。

开通白标账号

确认集成模式（A 渠道分销 / B 白标主商户 / C 聚合多租户）后，提交主体资料走 KYB 审核。

需要准备
公司注册证明、注册地址、业务描述、网站或 App、UBO 信息、结算账户
谁审核
YASBe 合规团队；模式 B / C 需额外评估你的牌照与合规能力
产出
B端门户账号（portal.yasbee.com）+ 白标主体 ID（ent_...）
耗时
资料齐全情况下通常 1–3 个工作日
ℹ️
沙盒不等 KYB白标门户开好后即可自助创建沙盒环境，无需等 KYB 通过。KYB 只影响 Live 密钥发放。

获取 API 密钥

在 B端门户 开发者设置 → API 密钥 中创建。沙盒密钥自助生成，生产密钥需审批。

环境密钥前缀获取方式IP 白名单
Sandbox sk_test_ 门户自助创建，即时生效，数量不限 可选（默认不限制）
Live sk_live_ KYB 通过 + 合规评估 + 结算账户就绪后由运营开通 必填
⚠️
密钥只能出现在你的服务端 密钥等同于资金操作权限。不要写进前端、App 包、公开仓库或日志；前端需要通过你自己的后端中转调用。 泄露时立即在门户吊销并重建 —— 吊销即时生效，进行中的请求不受影响。

环境与鉴权

两个环境完全隔离：数据、密钥、Webhook 互不相通。所有请求走 HTTPS，一律使用 Bearer 认证。

Sandbox
https://api-sandbox.yasbee.com/v1
  • 模拟数据，无真实资金
  • 可调用 /v1/sandbox/* 模拟端点
  • 数据 30 天滚动清理
VS
Live
https://api.yasbee.com/v1
  • 真实资金与真实通道
  • 无模拟端点
  • 数据长期保留，可导出对账单

方式一 · API Key 直连（推荐起步）

把密钥直接放进 Authorization 头，适合服务端单主体调用。

  -H "Authorization: Bearer sk_test_9f2c…" \
  -H "X-Request-Id: 7c1a9e04-2f6b…"
const res = await fetch('https://api-sandbox.yasbee.com/v1/customers?limit=2', {
  headers: {
    'Authorization': 'Bearer sk_test_9f2c…',
    'X-Request-Id': crypto.randomUUID()
  }
});
const { data } = await res.json();
import requests

res = requests.get(
    'https://api-sandbox.yasbee.com/v1/customers',
    params={'limit': 2},
    headers={'Authorization': 'Bearer sk_test_9f2c…'},
)
customers = res.json()['data']

方式二 · OAuth 2.0 换取短期令牌

需要细粒度授权（只读密钥、代下游子商户操作）时使用 client_credentials 换 access_token，有效期 3600 秒。

cURL复制
curl -X POST https://api-sandbox.yasbee.com/v1/oauth/token \
  -H "Content-Type: application/json" \
  -d '{
    "grant_type": "client_credentials",
    "client_id": "cli_test_4d81…",
    "client_secret": "cs_test_…",
    "scope": "customers:read virtual_accounts:write payouts:write"
  }'

# 200 OK
{
  "access_token": "at_9b31c7…",
  "token_type": "Bearer",
  "expires_in": 3600,
  "scope": "customers:read virtual_accounts:write payouts:write"
}

请求约定

这几条约定贯穿所有端点，读完可以省掉很多字段猜测。

约定规则示例
金额 一律用十进制字符串（不用浮点数、不用最小单位整数），避免精度误差与币种小数位差异。 "amount": "1250.00"
币种 法币用 ISO 4217 三位大写；加密资产用小写符号 + 链标识。 "currency": "USD"
"asset":"usdt","network":"TRC20"
时间 ISO 8601 UTC，带毫秒。不要传本地时间。 "created_at":"2026-09-15T08:21:33.412Z"
命名 请求与响应字段统一 snake_case；资源 ID 带类型前缀。 cus_ / va_ / pay_ / card_ / tx_
幂等 所有 POST 必须带 Idempotency-Key（建议 UUIDv4）。同键重放会返回首次结果。 Idempotency-Key: 6f0d2b91-…
分页 游标分页：limit（默认 20，最大 100）+ starting_after + 响应里的 has_more。 ?limit=50&starting_after=cus_3f81a2bc
追踪 可选传 X-Request-Id；我们会在响应和事件里原样回传，排查问题时提供给对接人。 X-Request-Id: 7c1a9e04-…

五个最常见的坑

  • 金额用浮点数 —— 前端算 0.1 + 0.2 传过来，对账差一分钱。统一用字符串。
  • 忘记 Idempotency-Key —— 网络超时重试后出现两笔出款。所有写操作都要带键。
  • 把 Webhook 当作唯一真相 —— 事件可能重复投递或延迟到达，必须落库幂等，并以主动查询作为兜底对账手段。
  • 拿沙盒行为推断生产 —— 沙盒只保证请求/响应结构与状态机一致，通道覆盖与时效不同。见 沙盒与生产的差异。
  • 密钥入前端 —— 移动端/浏览器里出现 sk_ 前缀即视为泄露，需立刻吊销。
