# YASBe 原型工作流规范（唯一权威）

> **生效**：2026-09-17 ｜ **适用范围**：本仓库所有原型页 / PRD / 验收文档
> **配套文件**：`../PROTOTYPE-LINKS.md`（登记清单，唯一链接索引）、`../tools/check_registry.py`（三闸校验器）
> 流程与本文件冲突时，以本文件为准；本文件变更需在提交信息中说明原因。

---

## 0. 三条定稿口径（2026-09-17 用户拍板）

| # | 口径 | 原文 | 落地含义 |
|---|---|---|---|
| P1 | **确认方式** | 「一般是我先本地预览，确定后才 push」 | 交付物 = 本地预览 + 改动清单；**不是**看助手截图，**不是**先上线再迭代 |
| P2 | **归档** | 「没有说要归档时不需要归档」 | 默认**不归档、只留最新版**：就地覆盖同一文件，不主动挪 `_archive/`、不主动升历史版本号。git 历史就是版本库，回看旧版用 `git show`。**用户明确说"归档"才归档。** |
| P3 | **定版语义** | 「我告诉你 push 基本就定版了」 | 说 `push` **即放行、即定版**，不需要再说"确认/放行"这类词，**没有** 24h 自动通过机制 |

## 1. 流水线 · 8 步 4 门禁

| 步 | 动作 | 门禁 | 谁做 |
|---|---|---|---|
| S0 | 需求输入：3 行需求卡（做什么 / 端别 / 验收点） | **G0 用户点头** | 用户 → 助手 |
| S1 | 命名即创建：按 §2 规范落地文件路径 | — | 助手 |
| S2 | 自检：跑 `product-output-self-check` + 浏览器实测（渲染、console 零报错、字段对齐现网真值） | — | 助手 |
| S3 | 交付确认：发本地预览（绝对路径 + 改动清单 + 字节数 + 断言） | **G1 用户本地确认** | 助手 → 用户 |
| S4 | 部署：精确 `git add` 本次文件 → commit（消息含业务+日期）→ push main | **G2 线上字节数 == 本地字节数** | 助手 |
| S5 | 登记：三处同步（见 §7） | **G3 三处都能 grep 到该链接** | 助手 |
| S6 | 回执：发线上链接 + 截图 + 登记回执 | — | 助手 |
| S7 | 迭代：回到 S2（同一文件就地覆盖，见 P3） | — | 助手 |
| S8 | 归档：**仅当用户明确要求** | — | 助手 |

**G1 是唯一硬门禁，也是唯一需要用户出手的地方。**
**G2 判据**：push 后约 1 分钟，拉线上文件与本地逐字节比对，**字节数相等**才算成功 —— 只看 HTTP 200 可能是旧缓存。
比对前**先把本地 CRLF 归一为 LF**：线上（git 存储版）是 LF，本地工作区可能是 CRLF，不归一会把纯行尾差异误判成"线上不是最新"。
**G3 判据**：`PROTOTYPE-LINKS.md` + 根 `index.html` + `admin/prototypes/index.html` 三处都能 grep 到，缺一处 = 未登记完成。

## 2. 命名与存放

**命名**（原型与 PRD 同一规则）：

```
YYYY-MM-DD_<业务模块>_<端别>[_版本].html     ← 原型页
YYYY-MM-DD_<业务模块>_<端别>[_版本].md       ← PRD / 验收 / 评审
```

- 日期在最前 → 文件夹内按文件名排序即时间序
- 业务模块在中 → 可检索
- **端别进文件名，不进文件夹**；端别取值：`管理端` / `客户端` / `B端` / `代币官网` / `白标门户`
- 同模块多稿才加 `_v0.2`；**日常迭代不加版本号，就地覆盖**（见 P3）
- 不再使用 `01-` `05-` 这类裸编号起名

**存放**：新产出统一进 `prototypes/<业务模块>/`，PRD 与原型同模块并置，**模块文件夹名不含端别**。

例：
```
prototypes/法币渠道/2026-09-17_法币交易审核_管理端.html
prototypes/法币渠道/2026-09-17_法币账户_客户端.html
prototypes/法币渠道/2026-09-17_法币渠道_PRD_管理端.md
```

**存量不迁移**：`admin/prototypes/*`、`client/prototypes/*` 下的旧文件保持原位。改名会打断大量内部互链、已外发的线上链接会 404。存量只登记、不改名、不搬家。

## 3. 状态机

```
DRAFT ──自检通过──> IN_REVIEW ──用户确认──> APPROVED ──push──> DEPLOYED ──三处登记──> REGISTERED
   ^                    │                                                                  │
   └──── 用户要求改 ─────┘                                                          ITERATING ──> (回到 DRAFT)
                                                                                          │
                                                              (仅用户要求) ARCHIVED / DROPPED
```

用户只在 `IN_REVIEW` 出手一次；其余 7 态助手自走。

---

## 4. 四条铁律

- **L1 命名即规范** —— 建文件的那一刻命名就合规，不靠事后改名
- **L2 一个整体目录** —— `prototypes/` 是唯一落点，存量不迁移
- **L3 未确认不部署** —— 用户没说 push 就不 push；**也不夹带**工作区其它已改文件（禁用 `git add .`）
- **L4 部署即登记** —— 同一轮内完成三处登记，不许拆到下一次

---

## 5. 防漏三闸（`tools/check_registry.py`）

| 闸 | 查什么 | 失败含义 |
|---|---|---|
| 闸 1 · 命名 | `prototypes/` 下的**新增**文件是否匹配命名正则 | 命名跑偏，检索不到 |
| 闸 2 · 覆盖 | 全仓可发布 `.html` / `.md` 与登记条目的差集，**扣除已知欠账基线** | 有新增漏登（`tools/registry_baseline.txt` 之外的新漏项） |
| 闸 3 · 一致性 | 登记表行尾 + 线上字节数 == 本地字节数 + 三处入口交叉核对 | 线上不是最新 / 死链 / 三处登记不同步 |

**每轮 push 前跑一次，有阻塞项不 push。** 用法见 `tools/check_registry.py` 头部注释。

## 7. 三处登记（push 后立即做）

1. **`PROTOTYPE-LINKS.md`** —— 对应业务分组内加一行（原型名称 / 功能 / 最后更新 / 链接）
2. **根 `index.html`** —— 仓库导航首页加条目
3. **`admin/prototypes/index.html`** —— 管理端总览加条目

三处任一缺失，就是下次用户说「X 不在里面」的根因。
**注意**：用户说「不在里面」时先分辨指哪一个 —— 三者长期不同步，登记表里有 ≠ 导航页里有。

## 8. 已知的坑（真实踩过）

- **CRLF**：`PROTOTYPE-LINKS.md` 在部分检出环境下会出现 CRLF；含 CRLF 的 md 禁用 `patch` 工具，改 bytes 级。改完用闸 3 核对行尾。
- **`git add .`**：会夹带工作区里其它未完成模块，push 出去的线上内容超范围。只精确 add 本次文件。
- **curl 在 MSYS**：`-o /dev/null -w` 会 exit 23；改用 `-o ./_r.html` + `wc -c` + `rm -f`。
- **HTTP 200 ≠ 已更新**：`*.github.io` 有缓存，必须比字节数。
- **线上是 LF 版**：本地 CRLF 文件与线上字节数天然差「行数」个字节（例：`index.html` 11542 − 210 CR = 11332 = 线上）。比对必须先归一化行尾，否则大批文件误报。
- **中文路径必须百分号编码**：登记表里若写裸中文 URL，脚本直接请求会抛异常（表现为"不可访问"）；`https://…/prototypes/返佣和奖励/x.html` 要请求成 `…/prototypes/%E8%BF%94%E4%BD%A3…/…`。`tools/check_registry.py` 已自动逐段编码。
- **线上索引比本地旧一版**：根因是提前改了登记文件但没同轮 push。现在 L4 保证两者同轮。
