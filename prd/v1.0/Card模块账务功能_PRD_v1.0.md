# YASBee 管理端 — Card 模块账务功能 PRD

## v1.0 — 2026-06-02

---

## 1. 产品概述

### 1.1 背景与目标

YASBee 管理后台（admin.beeznis.com）的 Card 模块已实现卡片生命周期管理（列表、详情、状态变更、限额管理）和基础交易记录展示。但**财务/账务层面的管理能力**目前缺失：

- 卡片费用结算记录不可查
- 月费/手续费账单无独立管理入口
- 无对账机制确保 YASBee 与 Interlace 账目一致
- 争议/拒付工单缺乏系统化管理
- 财务数据没有汇总看板

**目标**：构建完整的 Card 模块账务体系，使运营和财务人员能够一站式管理卡片相关的所有费用、账单、对账和财务分析。

### 1.2 范围

- **平台**：YASBee 管理后台 Web 端（React 18 + Ant Design）
- **目标用户**：
  - 财务人员：费用结算、对账
  - 运营人员：争议处理、退款操作
  - 管理员：财务看板监控
- **定位**：Card 模块下的增补功能（新增侧边栏子菜单或独立 Tab）

### 1.3 模块概览

| 子模块 | 说明 | 优先级 |
|--------|------|--------|
| 费用结算（Settlement） | 卡片费用明细及结算记录 | P1 |
| 账单管理（Billing） | 月费/手续费账单生成与查询 | P1 |
| 交易对账（Reconciliation） | YASBee vs Interlace 对账报告 | P1 |
| 争议与退款（Dispute & Refund） | 争议工单 + 退款申请管理 | P1 |
| 财务看板（Dashboard） | 多维财务数据概览 | P2 |

### 1.4 术语表

| 术语 | 含义 |
|------|------|
| Interlace | 发卡渠道商 |
| Settlement | 结算：Interlace 按周期结算的费用报告 |
| Chargeback | 拒付：持卡人对交易发起的争议 |
| FX Fee | 外汇兑换手续费 |
| Reconciliation | 对账：YASBee 系统数据与 Interlace 渠道数据的自动比对过程 |
| Match Rate | 匹配率：对账中双方数据一致的比例 |
| Diff | 差异：对账中发现的数据不一致项 |

### 3.3 交易对账模块（F-AC-021 ~ F-AC-026）

对账模块是整个账务体系的核心校验机制，负责自动比对 YASBee 侧与 Interlace 侧的**余额、交易流水、费用**，确保双方账目一致。

#### 3.3.1 对账执行引擎（F-AC-021）

| 字段 | 值 |
|------|-----|
| **优先级** | P1 |
| **用户故事** | 作为财务人员，我希望系统每日自动执行对账，并在对账完成后收到结果汇总，避免人工逐卡核对的低效和疏漏 |
| **功能描述** | 支持自动/手动触发的多维度对账引擎，生成对账报告 |

**对账维度**：

| 维度 | 内容 | 频率 | 比对方式 | 阈值 |
|------|------|------|---------|------|
| 余额对账 | 每张卡的 YASBee 余额 vs Interlace 单卡余额 | 日（03:00 UTC） | 逐卡 API 拉取比对 | 差值 ≤ $0.01 视为匹配 |
| 交易流水对账 | 当日交易记录完整性校验 | 日（03:00 UTC + 余额对账后） | 按交易 ID + 金额逐一配对 | 完全一致才匹配 |
| 费用对账 | 当月累计费用 vs Interlace 账单 | 月（账单生成后） | 费用类型逐项比对 | 每项费用分项对 |
| 汇总对账 | 全平台总余额 + 总交易额 | 日（交易对账后） | 聚合数据总差校验 | 总差 ≤ $0.10 |

**对账排序**：余额对账 → 交易流水对账 → 汇总对账（流水线执行，任一环节异常不阻断后续）

**对账报告状态机**：

```
执行中 RUNNING → 完成 MATCHED（全匹配）
               → 完成 DIFF_FOUND（有差异，等待处理）
               → 失败 FAILED（执行异常，需要重试）
```

**对账报告字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| 对账 ID | string | REC-YYYYMMDD-xxx |
| 对账日期 | date | 2026-06-01 |
| 执行时间 | datetime | 2026-06-02 03:00:15 |
| 执行方式 | enum | AUTO / MANUAL |
| 对账结果 | enum | MATCHED / DIFF_FOUND / FAILED |
| 匹配率 | decimal | 99.85%（匹配卡片数 / 总卡片数 × 100%） |
| 总卡片数 | int | 参与对账的卡片数 |
| 匹配卡片数 | int | 余额一致（差值 ≤ $0.01）的卡片数 |
| 差异卡片数 | int | 存在差异的卡片数 |
| YASBee 总余额 | decimal | 本系统统计余额 |
| Interlace 总余额 | decimal | 渠道统计数据 |
| 差异总金额 | decimal | Σ|单卡差值| |
| 净偏差金额 | decimal | Σ(YASBee - Interlace) 可正可负 |
| 差异明细 | file | 差异详情 CSV |
| 执行耗时 | int | 秒，用于监控对账性能 |

#### 3.3.3 自动修复 & 智能对账（F-AC-023）

| 字段 | 值 |
|------|-----|
| **优先级** | P2 |
| **用户故事** | 作为财务人员，我希望系统能自动处理小额差异和可识别的常见差异，减少我的手工作业量 |
| **功能描述** | 小额差异自动标记、常见差异自动修复推荐 |

**自动修复规则**：

| 触发条件 | 自动行为 | 说明 |
|---------|---------|------|
| 差额 ≤ $0.01 | 自动标记为「已处理—小额差异」 | 金额精度误差，无需人工介入 |
| 差额 = $35.00 且卡片当日有 Chargeback | 自动标记为「已处理—拒付费」 | 拒付费从余额中扣除导致的差异 |
| 差额 = $月费 且卡片当月有月费记录 | 自动标记为「已处理—月费扣减」 | 月费扣除时差导致的暂时差异 |
| 流水缺失（YASBee 有 / Interlace 无）且金额 ≤ $10 | 自动标记「待人工确认—小额流水」 | 系统不自动修复，但降低优先级 |
| 状态不匹配（Active vs Closed） | 自动生成「卡片状态同步任务」推送运营 | 推送到待办列表 |

**智能建议**：

对于无法自动修复的差异，系统根据历史处理模式给出建议：如「该卡片上月同样存在 $50 差额，上次处理方式为『已确认』，是否采用相同操作？」

**费用比对维度**：
