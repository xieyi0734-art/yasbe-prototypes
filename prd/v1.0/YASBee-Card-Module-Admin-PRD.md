## 1. 产品概述

### 1.1 文档版本历史

| 版本 | 日期 | 修改人 | 修改内容 |
|------|------|--------|---------|
|| v1.0 | 2026-05-21 | Hermes | 初始版本，基于线上 YASBee 管理后台反编译 |
|| v2.0 | 2026-06-03 | Hermes | 新增交易与结算、充值/扣款/退款两大模块 |

### 1.2 产品简介

- **产品名称**：YASBee 管理后台（YASBee Admin）
- **定位**：虚拟卡发卡平台的管理控制台，供运营/客服/管理员管理平台卡片生命周期
- **目标用户**：
  - 超级管理员：系统全局配置、风控规则（本篇不涉及）
  - 运营人员：卡片发放、用户权限管控、渠道管理
  - 客服人员：用户查询、卡片状态管理、限额调整
- **核心价值**：为没有技术背景的运营/客服团队提供一站式卡片生命周期管理工具
- **文档范围**：本篇聚焦 **Card 模块**的管理端功能，涵盖两个入口：
  1. **卡片管理**（独立页面） — 全局卡片列表视图
  2. **客户详情 → Cards Tab** — 单用户维度卡片列表视图

### 1.3 产品边界

| 维度 | In Scope | Out of Scope |
|------|----------|-------------|
| 功能 | 卡片列表/筛选/状态管理/限额查看、客户关联卡片、<br>交易流水与结算、充值/扣款/退款 | 报表统计（本期不涉及） |
| 操作 | 冻结/解冻/关闭卡片、查看详情、发新卡、<br>手动充值/扣款、发起退款 | 批量操作（本期不涉及） |
| 数据 | 卡片基础信息、余额/消费/限额、<br>交易流水明细、汇总结算数据 | — |
| 配置 | — | 渠道管理、卡务配置、费率配置、系统配置 |

## 2. 用户研究与需求分析

### 2.1 用户画像

| 用户类型 | 特征 | 痛点 | 目标 |
|---------|------|------|------|
| 运营人员 | 负责卡片发放和日常管理 | 无法快速筛选特定状态/类型卡片 | 快捷查询和管理全局卡片 |
| 客服人员 | 处理用户卡片使用问题 | 需要同时查看用户信息和卡片信息 | 从用户维度管理卡片 |
| 风控人员 | 监控异常卡片行为 | 卡片状态变更缺乏可视化入口 | 快速冻结/关闭异常卡片 |

### 2.2 管理端入口架构

```
YASBee 管理后台
├── Dashboard
├── 客户管理
│   ├── 概览
│   ├── 审核验证
│   └── 客户列表
│       └── 客户详情
│           ├── Personal Info
│           ├── Bank Account
│           ├── Crypto wallet
│           ├── Convert
│           ├── Cards (← 本文档)
│           └── Investment
├── 资产管理（法币/加密货币/兑换）
├── 卡片管理 (← 本文档)
├── 配置
│   ├── 渠道管理
│   ├── 卡务管理
│   ├── 投资管理
│   └── 系统管理
```

| **功能编号** | MF-C001 |
| **功能名称** | 卡片列表视图 |
| **优先级** | P0 |
| **用户故事** | 作为运营人员，我希望在卡片管理页面看到所有卡片的概况和统计，以便快速了解平台卡片整体状态 |
| **功能描述** | 提供全局卡片列表，包含统计摘要（4个统计卡片）、筛选过滤（状态下拉+卡号搜索）、数据表格展示、分页导航 |

| **后置条件** | — |

**界面元素**：

① **统计卡片行**（4个）
| 统计项 | 示例值 |
|--------|--------|
| 总余额 | $24,580.00 |
| 总消费 | $142,680.50 |
| 交易中余额 | $3,245.60 |
| 卡片总数 | 8 |

② **筛选栏**
| 筛选项 | 组件类型 | 说明 |

| 发新卡按钮 | 按钮（右侧） | "+ 发新卡" 带黄色按钮，右侧对齐 |

③ **数据表格**（11列）

| 列 | 类型 | 示例值 | 说明 |
|----|------|--------|------|
| 卡号 | 文本（等宽） | 480********4821 | 显示前3位+掩码+后4位 |
| 卡片名称 | 文本 | YASBee | — |
| 渠道 | 文本 | Interlace | 发卡渠道名称 |
| 有效期 | 文本 | 05/28 | MM/YY 格式 |
| 安全码 | 文本 | *** | 掩码显示（3位星号） |
| 标签 | 标签（彩色） | 营销推广 / 运营 / 订阅 / 差旅 | 4种颜色标签 |
| 余额 | 货币 | $2,580.00 | 当前余额 |

| 已冻结 | `#FEF9C3` | `#854D0E` | 临时冻结 |
| 已关闭 | `#FCE7F3` | `#9D174D` | 永久关闭 |

**标签颜色映射**：

| 标签 | Badge 颜色 | 说明 |
|------|-----------|------|
| 营销推广 | `#8B5CF6` 紫色 | 营销用卡 |
| 运营 | `#3B82F6` 蓝色 | 运营用卡 |

**业务规则**：

- 卡片列表按创建时间倒序排列（最新卡片在前）
- 已关闭的卡片操作列只显示"详情"，不显示"冻结"按钮
- 已冻结的卡片操作列显示"解冻"和"详情"两个按钮
- 数据表格列名使用英文

**异常流程**：

| 异常情况 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 无搜索结果 | 表格显示空状态 | "暂无数据" |
| 网络加载失败 | 显示错误提示 | "网络异常，请稍后重试" |

**分页**：默认每页5条，显示"显示 X-Y 条，共 N 张卡片，M页"，可选切换页码。

**API 接口**：

| 方法 | Endpoint | 用途 |
|------|----------|------|
| GET | `/apiAdmin/card/list` | 获取全局卡片列表 |
| 参数 | pageNo, pageSize, status, cardNumber | 分页+筛选 |

#### MF-C002 卡片状态管理

| 字段 | 值 |
|------|-----|
| **功能编号** | MF-C002 |
| **功能名称** | 卡片状态管理（冻结/解冻/关闭） |
| **优先级** | P0 |
| **用户故事** | 作为运营/客服人员，我希望能够一键冻结或关闭异常卡片，以便快速控制风险 |
| **功能描述** | 在卡片列表和客户卡片列表的操作列中，提供"冻结/解冻/关闭"操作按钮，点击后弹出确认弹窗 |
| **前置条件** | 目标卡片存在且当前状态允许操作 |
| **后置条件** | 卡片状态更新，列表刷新 |

**操作矩阵**：

| 当前状态 | 可执行操作 | 操作后状态 | 操作列显示 |
|---------|-----------|-----------|-----------|
| 使用中 | 冻结 | 已冻结 | 冻结 / 详情 |
| 已冻结 | 解冻 | 使用中 | 解冻 / 详情 |
| 已关闭 | 无 | — | 详情 |

**确认弹窗文案**：

| 操作 | 确认标题 | 确认文案 | 确认按钮 |
|------|---------|---------|---------|
| 冻结 | 确认冻结 | 确定要冻结该卡片？冻结后所有交易将被中断 | 确认冻结 |
| 解冻 | 确认解冻 | 确定要解冻该卡片？解冻后卡片恢复正常使用 | 确认解冻 |
| 关闭 | 确认关闭 | 确定要关闭该卡片？关闭后不可恢复 | 确认关闭 |

**业务规则**：

- 已关闭的卡片无法重新激活（终态）
- 状态变更操作需二次确认弹窗
- 操作完成后自动刷新列表

**异常流程**：

| 异常情况 | 处理方式 | 用户提示 |
|---------|---------|---------|
| 卡片已被其他管理员操作 | 提示冲突 | "卡片状态已变更，请刷新后重试" |

### 3.2 交易与结算（Transaction & Settlement，新增 v2.0）

#### 3.2.1 功能模块说明

| 项目 | 内容 |
|------|------|

### 3.3 充值/扣款与退款（Recharge / Deduct / Refund，新增 v2.0）

#### 3.3.1 功能模块说明

| 项目 | 内容 |
|------|------|
| **模块定位** | 提供对卡片余额的手动操作入口，包括充值/扣款/退款审批流程 |

4. **退款**：针对已完成的交易发起退款，经审批后执行

### 8.1 术语表

| 术语 | 定义 |
|------|------|
| 卡片生命周期 | 从发卡到关闭的全过程 |
| 使用中 (Active) | 卡片正常可用状态 |
| 已冻结 (Frozen) | 卡片临时暂停交易 |
| 已关闭 (Closed) | 卡片永久关闭，不可恢复 |
| 单笔限额 | 单张卡片单笔交易最大金额 |

| 费用交易 | 开卡费/月费/充值费/消费手续费等平台收取的费用 |
| 充值 (Recharge) | 手动增加卡片可用余额 |
| 扣款 (Deduct) | 手动减少卡片可用余额 |
| 退款 (Refund) | 针对已完成交易的逆向资金操作 |
| 审批流 | 退款/余额调整等操作的多级审批流程 |
| 净收入 | 费用交易总额，即平台在该周期内的收入 |
