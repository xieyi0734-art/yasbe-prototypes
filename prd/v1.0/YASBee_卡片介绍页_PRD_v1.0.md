## 1. 产品概述

### 1.1 背景与目标
YASBee 现阶段已对接 Interlace 发卡渠道，管理端（admin.beeznis.com）已实现卡片服务管理、用户卡片管理等功能。为向用户端消费者展示卡片产品，需设计一个**卡片介绍页（Card Introduction Page）**，让用户直观了解卡片的外观设计、费用结构、支持的业务场景，并引导用户进入开卡流程。

### 1.2 范围
- **平台**: Web 端（响应式，桌面优先）
- **访问入口**: 用户端后台 / 官网产品页
- **目标用户**: 有跨境消费、在线支付需求的终端用户
- **定位**: 产品展示 + 转化引导页

### 1.3 术语表
| 术语 | 含义 |
|------|------|
| 虚拟卡 | 无实体卡基，仅以数字形式存在的支付卡（CardModel=0） |
| Prepaid | 预付卡，需先充值后消费 |
| Interlace | 发卡渠道商 |
| ditch_card | 管理端卡片产品配置数据表 |

## 2. 用户研究

### 2.1 用户画像
- **用户 A — 跨境消费者**: 经常在海外电商购物，需要一张低费用的虚拟卡完成支付
- **用户 B — 数字资产用户**: 用加密货币兑换法币后充值到卡片，用于日常在线消费
- **用户 C — 订阅用户**: 需要虚拟卡绑定 SaaS、流媒体等月费订阅服务

### 2.2 用户需求
1. 快速了解卡片的外观和品牌调性
2. 清楚地了解所有费用项目，没有隐藏费用
3. 知道这张卡能用在哪里、支持哪些场景
4. 明确的下一步操作指引（申请开卡）

### 2.3 使用场景
- 用户从官网点击"了解卡片"进入介绍页
- 用户在管理后台看到卡产品列表后，点击进入详情介绍

## 3. 功能需求

### F-001 卡片展示区
- **优先级**: P0
- **用户故事**: 作为用户，我希望看到卡片的外观设计，对卡片品牌有直观认知
- **业务规则**:
  - 展示一张 3D 效果的虚拟卡正面图
  - 卡面应展示：卡名、品牌标识（YASBee）、卡 BIN 掩码（示例号码）
  - 卡片图片应通过 3D 透视（perspective + rotateY/rotateX）营造立体感
  - 支持深色主题背景（渐变蓝灰或深色渐变）
- **异常流程**: 若卡片图片 URL 为空，显示默认卡面设计

### F-002 费用摘要区
- **优先级**: P0
- **用户故事**: 作为用户，我想一眼看到最关心的费用项
- **业务规则**:
  - 展示 4 项核心费用的摘要卡片：开卡费、月费、消费费、充值费
  - 每项显示：费用名称 + 金额/比例
  - 无需二次点击，直接展示关键数字
- **数据来源**: `ditch_card` → openingFee / openingFeeRate, consumptionFeeRate / consumptionFixedFee, rechargeFeeRate / rechargeFixedFee
- **默认值**: 费用为 0 时展示 "$0" 而非 "免费"（保持一致）

### F-003 费用明细表
- **优先级**: P1
- **用户故事**: 作为用户，我想查看所有费用的详细说明，确保没有隐藏费用
- **业务规则**:
  - 以表格/列表形式展示所有费用项
  - 费用项包括：
    1. 开卡费（Card Issuance Fee）
    2. 月费（Monthly Fee）
    3. 消费费率（Transaction Fee Rate）
    4. 消费固定费（Transaction Fixed Fee）
    5. 充值费率（Top-up Fee Rate）
    6. 充值固定费（Top-up Fixed Fee）
    7. 首开优惠（First Issue Discount）
    8. 最低充值额（Minimum Top-up Amount）
    9. 货币兑换费（Currency Conversion Fee）— 预留
    10. 销户费（Account Closure Fee）— 预留
  - 每行：费用名称 + 金额/比例 + 说明
  - 零费用项不隐藏，展示 "$0" 或 "0%" 以示透明

### F-004 支持币种展示
- **优先级**: P1
- **用户故事**: 作为用户，我想知道卡片支持哪些币种
- **业务规则**:
  - 展示卡片支持的货币
  - 展示方式：标签列表，当前支持的币种高亮
  - 当前渠道默认为 USD，额外展示常见法币标签作为参考

### F-005 支付方式/钱包绑定
- **优先级**: P1
- **用户故事**: 作为用户，我想知道这张卡能不能绑定到我的 Apple Pay 或 Google Pay
- **业务规则**:
  - 展示支持的支付绑定方式：
    - Online Payment（线上支付）
    - Offline Payment（线下 POS / ATM）
    - Apple Pay
    - Google Pay
  - 状态：绿色对号 ✅/红色叉号 ❌ 表示支持/不支持

### F-006 业务场景展示
- **优先级**: P1
- **用户故事**: 作为用户，我想知道这张卡可以用在哪些地方
- **业务规则**:
  - 以宫格（3 列或 4 列）展示业务场景
  - 每个场景包含：icon（emoji或SVG名）+ 场景名称 + 简短说明
  - 场景建议（基于 Interlace 虚拟卡 Prepaid 类型）：
    1. Online Shopping — 在线购物
    2. POS Spending — 线下POS消费
    3. Wallet Top-up — 钱包充值
    4. Currency Exchange — 币种兑换
    5. Bill Payment — 账单支付
    6. Digital Wallet — 数字钱包绑定
    7. Subscription — 订阅服务
    8. Travel — 旅行消费
  - icon 使用与品牌色调（#E59303）搭配的视觉效果

### F-007 引导 CTA 按钮
- **优先级**: P0
- **用户故事**: 作为用户，看完介绍后我想知道怎么申请这张卡
- **业务规则**:
  - 页面底部展示主 CTA 按钮 "Apply Now" 或 "立即申请"
  - 按钮颜色使用品牌色 #E59303 或白色描边
  - 点击跳转到开卡申请流程页面
  - CTA 应保持在视线范围内（页面底部固定区域）

## 4. 非功能需求

### 4.1 外观风格
- **主题**: 深色主题（Dark Theme），渐变蓝灰背景
- **品牌色**: #E59303（YASBee 品牌橙）
- **字体**: 无衬线字体，标题可加粗
- **布局**: 单列布局，从上到下依次展示各模块
- **卡片**: 圆角 12px~16px，轻微阴影质感
- **间距**: 各模块之间留白充足（40px~60px）

### 4.2 响应式
- 桌面端优先（1440px 设计宽度）
- 平板端（768px~1024px）：部分模块调整为 2 列
- 移动端（<768px）：单列布局，费用宫格 2x2

### 4.3 性能
- 纯静态 HTML + CSS，无需后端数据请求
- 数据嵌入为 JavaScript 配置对象，便于后续对接 API
- 无外部依赖（除 Google Fonts 可选）

### 4.4 可维护性
- 数据层与展示层分离：卡片配置数据放在 JS 对象 `cardConfig` 中
- 修改费用/币种/场景只需改数据对象，无需改 HTML 结构

## 5. 数据需求

### 5.1 数据来源
数据基于管理端 `ditch_card` 表字段，当前卡片数据如下：

| 字段 | 值 | 说明 |
|------|-----|------|
| name | Test1 | 卡名 |
| ditchName | Interlace | 渠道名称 |
| cardModel | 0 | 虚拟卡 |
| cardType | 0 | Prepaid |
| openingFee | 0.00 | 开卡费 |
| openingFeeRate | 0 | 开卡费率 |
| consumptionFeeRate | 0 | 消费费率 |
| consumptionFixedFee | 0 | 消费固定费 |
| rechargeFeeRate | 0 | 充值费率 |
| rechargeFixedFee | 0 | 充值固定费 |
| firstOpenDiscount | 0 | 首开优惠 |
| rebateRate | 0 | 返佣率 |
| supportCurrency | USD | 支持货币 |
| supportGoogleWallet | 0 | 不支持Google Pay |
| supportApplePay | 0 | 不支持Apple Pay |

### 5.2 页面加载数据流
```
管理端 API (/apiAdmin/ditch/card/list)
      ↓
    cardConfig JS 对象（页面内嵌或异步获取）
      ↓
    渲染展示区、费用区、场景区等各模块
```
