## 1. 产品概述

### 1.1 背景与定位

本文档是 **YASBee × Interlace MoR 虚拟卡产品** 的**管理端（运营后台）配套文档**，定义运营人员、风控人员、管理员在后台对 Card 模块的管理能力。

**核心原则**：管理端是用户端的"管理视角"——用户端有的每项功能，管理端应有对应的查看、审核、配置、干预能力。

### 1.2 用户角色与权限

| 角色 | 管理端职责 | 涉及模块（本节） |
|------|-----------|----------------|
| **运营人员** | 客户卡片查看、充值、冻结/解冻、费用查询 | §2 卡片管理、§3 费用管理 |
| **风控人员** | 限额编辑、卡片状态操作、交易异常处理 | §2.3、§2.6 |
| **管理员** | 费用配置、返佣阶梯配置、等级限额模板配置 | §3 费用管理 |
| **客服** | Chargeback 工单、卡片信息查询 | 后续迭代 |

### 1.3 系统架构

- **前端**：React 18 + Ant Design + Tailwind CSS
- **状态管理**：Zustand
- **路由**：React Router v6
- **API 基地址**：`/apiAdmin/`
- **设计主色**：`#E59303`（金色）

| **功能名称** | 卡片状态管理 |
| **优先级** | P0 |

| **前置条件** | 卡片状态符合切换逻辑 |
| **对应用户端** | F-151 冻结/解冻、F-154 注销卡片、F-155 自助解冻 |

**状态流转规则**：

```
用户端操作 → 管理端同步显示
管理端切换 → 用户端同步更新

状态转换矩阵：
┌──────────┬─────────┬─────────┬─────────┐
│ 从 \\ 到 │ Active  │ Frozen  │ Closed  │
├──────────┼─────────┼─────────┼─────────┤
│ Active   │    —    │ 运营/风控│ 运营/风控│
│ Frozen   │运营/风控│    —    │ 运营/风控│
│ Closed   │   ❌    │   ❌    │    —    │
└──────────┴─────────┴─────────┴─────────┘
```

**验收标准 (AC)**：

| 编号 | 验收标准 |
|------|---------|
| AC-C401-01 | Active → Frozen 后，卡片列表余额仍显示，用户端显示"卡片已冻结" |
| AC-C401-02 | Active → Closed 需二次确认，确认后不可逆，卡片列表不再显示该卡 |
| AC-C401-03 | 风控冻结的卡片，用户端自助解冻（F-155）操作后，管理端状态同步更新为 Active |

### 2.10 拒付率监控

| 功能编号 | MF-F401 |
|---------|---------|
| **功能名称** | 拒付率监控 |
| **优先级** | P0 |
| **用户故事** | 作为风控/运营人员，我希望实时监控平台的月度拒付率和趋势，以便在接近阈值时提前预警并采取措施 |
| **功能描述** | 展示当月拒付率、预警线/惩罚线状态和近 6 个月趋势图 |
| **界面元素** | ① 大数字展示：当月拒付率（百分比）<br>② 进度条/阈值指示：4% 预警线（黄色标记）/ 5% 惩罚线（红色标记）<br>③ 趋势图：近 6 个月拒付率折线图<br>④ 状态提示：达到 4% 时提示"接近惩罚线，建议排查高风险客户"；达到 5% 时提示"已触发失败交易费惩罚" |
| **前置条件** | 运营/风控/管理员已登录 |

| 编号 | 验收标准 |

| AC-F401-02 | 拒付率 ≥ 4% 时系统自动发送通知（运营告警） |
| AC-F401-03 | 拒付率 ≥ 5% 时自动触发失败交易费 $0.50/笔（不可人工干预关闭） |
