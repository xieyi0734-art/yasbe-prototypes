# PRD：二次验证 — 出金场景

## 1. 产品概述

### 1.1 背景

平台当前仅 Crypto 出金有邮箱验证，Fiat 和 Exchange 出金均无二次验证。存在资金安全风险。

### 1.2 目标

为所有出金操作增加二次验证，用户可绑定 TOTP 提升安全等级，未绑定则回退邮箱验证码。

### 1.3 范围

| 模块 | 操作 | 当前状态 | 目标 |
|------|------|---------|------|
| Crypto | 链上提款 | 已有邮箱验证 | 升级为邮箱 + TOTP |
| Fiat | 银行出金 | 无验证 | 新增邮箱 + TOTP |
| Exchange | 兑换转出 | 无验证 | 新增邮箱 + TOTP |

> 验证仅在**提交出金请求时**触发，不作用于登录、存款等其他操作。

---

## 2. 验证方式（邮箱 + TOTP 二选一）

### 2.1 核心逻辑

| 用户状态 | 验证方式 | 说明 |
|---------|---------|------|
| 未绑定 TOTP | 邮箱验证码 | 默认方式，所有用户可用 |
| 已绑定 TOTP | TOTP 6 位码 | 绑定后自动升级，优先使用 |
| TOTP 验证失败 | 可切换邮箱验证码 | 兜底机制，防设备丢失 |

### 2.2 验证约束

- 验证码有效时长：5 分钟
- 最大尝试次数：5 次（超限后本次出金请求取消，需重新发起）
- 邮箱验证码由后端发送，复用 Crypto 已有邮件能力
- TOTP 基于 RFC 6238，30 秒刷新周期

---

## 3. 用户端（C 端）交互

### 3.1 出金验证弹窗

用户在出金页面填写参数后点击"提款"→ 弹出二次验证弹窗：

**已绑定 TOTP 时：**

```
┌──────────────────────────────┐
│       二次验证               │
│                              │
│   ┌──── TOTP 6 位码 ────┐   │
│   │  [   输入 6 位验证码  ] │   │
│   └──────────────────────┘   │
│                              │
│   ⚠ 验证码丢失？使用邮箱验证 │   │
│                              │
│   [取消]          [验证]     │
└──────────────────────────────┘
```

**未绑定 TOTP（或点击邮箱切换后）：**

```
┌──────────────────────────────┐
│       二次验证               │
│                              │
│   验证码已发送至邮箱          │
│   xieyi***@gmail.com         │
│                              │
│   ┌─── 邮箱验证码 ─────┐    │
│   │  [   输入 6 位验证码  ] │   │
│   └──────────────────────┘   │
│                              │
│   未收到？[重新发送]         │
│                              │
│   [取消]          [验证]     │
└──────────────────────────────┘
```

### 3.2 弹窗状态流转

```
用户点击"提款"
     ↓
弹出二次验证弹窗
     ↓
[已绑定 TOTP]                   [未绑定 TOTP]
显示 TOTP 输入框                显示邮箱验证码输入框
     ↓                                ↓
输入 6 位码 → 验证通过             输入验证码 → 验证通过
     ↓                                ↓
出金请求提交成功 → 弹窗关闭        出金请求提交成功 → 弹窗关闭
     ↓                                ↓
验证失败（≤5次）→ 提示错误         验证失败（≤5次）→ 提示错误
     ↓                                ↓
超时（5分钟）→ 弹窗关闭           超时（5分钟）→ 弹窗关闭
出金取消，需重新发起              出金取消，需重新发起
```

### 3.3 安全设置页面

在 C 端用户中心/账户设置中新增 TOTP 绑定入口。

**绑定流程：**

```
安全设置 → 二次验证
     ↓
点击"绑定 TOTP"
     ↓
弹窗显示以下内容：
┌──────────────────────────────┐
│     绑定 TOTP 验证器         │
│                              │
│  1. 下载 Google Authenticator│
│                              │
│  2. 扫码或输入密钥            │
│  ┌────────────────────────┐  │
│  │   [    二维码区域    ]  │  │
│  └────────────────────────┘  │
│  密钥: YASBEE-XXXX-XXXX      │
│                              │
│  3. 输入 6 位码确认          │
│  [   输入验证码    ]         │
│                              │
│  [取消]          [确认绑定]  │
└──────────────────────────────┘
```

**解绑流程：**
- 点击"解绑" → 发送邮箱验证码确认身份
- 验证通过 → 移除 TOTP 绑定 → 出金验证退回到邮箱验证码

**绑定状态展示：**

```
┌──────────────────────────────┐
│  二次验证                    │
│                              │
│  当前验证方式                │
│  ● Google Authenticator      │
│    已绑定（2026-07-01）      │
│    [解绑]                    │
│                              │
│  或使用邮箱验证码作为备选    │
└──────────────────────────────┘
```

## 4. Admin 管理端

### 4.1 安全配置页面

新增页面（或放已有配置区），位置：侧边栏 → Security Settings（暂定）

**配置项：**

| 配置项 | 类型 | 默认值 | 说明 |
|-------|------|-------|------|
| 二次验证总开关 | Toggle | 开启 | 全局开关 |
| Crypto 验证 | Toggle | 开启 | 独立控制 |
| Fiat 验证 | Toggle | 开启 | 独立控制 |
| Exchange 验证 | Toggle | 开启 | 独立控制 |
| 验证方式 | 下拉 | 邮箱+TOTP | 可扩展其他方式 |
| 最大失败次数 | 数字输入 | 5 | 超限后出金取消 |
| 验证码有效期 | 数字输入(分钟) | 5 | |

### 4.2 客户详情 → TOTP 状态

在客户详情页展示 TOTP 绑定状态字段：

- 状态：已绑定 / 未绑定
- 绑定时间
- 解绑记录（操作人、时间）

---

## 5. 后端逻辑

| 功能 | 说明 |
|------|------|
| 发送邮箱验证码 | 复用 Crypto 现有邮件能力 |
| TOTP 校验 | RFC 6238，30 秒周期 |
| 验证状态管理 | 通过后后台标记出金为"待审核" |
| 失败计数器 | 单次出金请求内有效，超限请求失效 |
| 密钥存储 | TOTP secret 加密存储，仅用户可见 |
| 绑定/解绑日志 | 记录操作人、IP、时间 |

---

## 6. 数据需求

### 用户 TOTP 绑定表（`user_totp_bindings`）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | PK |
| customer_id | bigint | 关联用户 |
| secret | string | TOTP 密钥（加密存储） |
| status | enum | enabled / disabled |
| bound_at | datetime | 绑定时间 |
| unbound_at | datetime | 解绑时间（可为 null） |

### 出金验证记录表（`withdrawal_verifications`）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | PK |
| withdrawal_id | bigint | 关联出金请求 |
| type | enum | email / totp |
| attempts | int | 已尝试次数 |
| max_attempts | int | 最大次数（5） |
| expires_at | datetime | 验证码过期时间 |
| status | enum | pending / verified / expired / failed |

---

## 7. 验收标准

| # | 验收标准 |
|---|---------|
| AC-01 | 未绑定 TOTP 的用户提交出金时收到邮箱验证码，输入正确后请求提交成功 |
| AC-02 | 已绑定 TOTP 的用户提交出金时显示 TOTP 输入框，输入正确 6 位码后请求提交成功 |
| AC-03 | TOTP 用户可选择切换为邮箱验证码 |
| AC-04 | 连续 5 次验证失败后出金请求取消，需重新发起 |
| AC-05 | 5 分钟内未完成验证，弹窗自动关闭，出金取消 |
| AC-06 | 用户在安全设置中可扫码绑定 TOTP，输入验证码确认后绑定成功 |
| AC-07 | 绑定 TOTP 后出金验证自动使用 TOTP |
| AC-08 | 解绑 TOTP 需邮箱验证身份，解绑后退回邮箱验证 |
| AC-09 | Admin 可独立控制各模块的二次验证开关 |
| AC-10 | TOTP 密钥加密存储，Admin 不可读取明文 |
