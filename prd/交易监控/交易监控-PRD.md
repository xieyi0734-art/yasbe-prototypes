## 1. 目标与依据

对纳入范围的成功交易实施事后交易监控，提供交易上送核对、告警案件调查和处理留痕。运营可以回答：哪位客户、哪类业务、何时、因什么规则触发、涉及哪些交易、由谁处理以及处理结果是否同步。

依据：

- 用户此前确认的范围：Crypto Wallet 成功链上入金／出金；VA 仅 OpenPayd EUR／GBP 成功入金／出金；Card 充值与 Card 转出到 Crypto Wallet，关注充值后快速转出。
- [在线 Scoping Sheet](https://docs.google.com/spreadsheets/d/1v-cyQqa2HzML41J86wssPyUMF9cIAkopHmKNVMBJITA/edit?gid=1002527305#gid=1002527305)。本次优先核对本地文件 `Apex Markets Inc _ Mesh TM Scoping Sheet.xlsx`，依据交易 Schema 工作表及 `4. Scenarios` 第 7–25 行；字段来源见第 6 节。下载快照不等于生产配置或已签署接口契约。
- [原型目录](../../prototypes/交易监控/index.html)。样例数据全部虚构，不连接 CA，不执行任何真实资金操作。

## 2. 业务边界

| 业务 | 本期纳入事件 | 监控目的 | 排除或约束 |
| --- | --- | --- | --- |
| Crypto Wallet | 成功链上入金、成功链上出金 | 金额、笔数异常 | 非链上内部划转不得伪装成链上交易；失败／处理中交易不计入成功交易监控 |
| VA | OpenPayd EUR／GBP 成功入金、成功出金 | 金额、笔数异常 | 不将 USD／Bridge 纳入本期 |
| YASBe Card | 充值、Card 转出到 Crypto Wallet | 识别充值后快速转出 | 不含开卡、消费、拒付、ATM；消费由 Interlace 既有监控覆盖。充值来源、成功节点、规则阈值待确认 |

本期不开发规则编辑器，不因规则表出现其他规则而扩充业务范围。地址筛查与本模块分开：不沿用地址风险等级来推定 CA 案件优先级。当前交易已成功，页面不提供放行、拒绝、冻结或退款操作；案件结论也不得触发这些资金动作。

Card 转 Wallet 为同一内部转移事件。可保留卡侧与钱包侧记账关联，但不能将钱包到账再次统计为链上入金。客户 UID 是平台归属标识；`customer_identifier.id` 与平台 UID 的映射、租户隔离和多账户归属须在接入时确认。

## 3. 新版规则对产品的影响

| 表内规则 | 来源 | 本次需求表达 |
| --- | --- | --- |
| RL_0013 / RL_0014 单笔出／入金额 | 第 8–9 行 | 保留方向、原币金额、折算金额与币种、阈值。表内为 `> 100,000`，不能擅自解释成 USD 或 USDT |
| RL_0015 入金笔数 | 第 10–12 行 | 分别按 BANK_PAYMENT、CARD_PAYMENT、CRYPTO 过滤，按 `{customer_identifier.id, type}` 统计入金。表内 7 calendar_days、`> 3` |
| RL_0016 出金笔数 | 第 13–15 行 | 同上，方向 OUTBOUND；入／出不可混计 |
| RL_0017 入金累计金额 | 第 16–18 行 | 按客户＋type 统计 `base_value.amount`；表内 7 calendar_days、`> 100,000` |
| RL_0018 出金累计金额 | 第 19–21 行 | 同上，方向 OUTBOUND |
| 余额比例、余额上限、首次交易等其他规则 | 第 7、22–25 行等 | 仅作为供应商规则资料，不自动新增本期需求 |

产品上需要同时展示业务类型、统计对象、规则方向、统计窗口、阈值和实际值。不能仅按客户合并 Bank／Card／Crypto，也不能只凭 RL 编号合并不同类型的规则实例；需保留上游实例标识或其明确的区分字段，具体契约待确认。

注意：

1. `7 calendar_days` 不直接改写为滚动 168 小时，窗口起止、时区及当前交易是否计入以确认后的 CA 契约为准。
2. 金额累计使用供应商认可的折算口径。原币、原始金额、折算币种、折算金额、汇率及汇率时间分开保留；缺失时展示“暂未获取”，不得把 USD 与 USDT 或 EUR 与 GBP 直接相加。
3. 表内 Outcome 为 Allow、Priority 为 P7 - Low。Allow 不等于平台需设置“放行”动作；P7 不映射为地址筛查的 0–5 等级。
4. 表内给出 Card 类型的金额／笔数配置，并不代表用户已追加 Card 全量金额／笔数监控需求。当前 Card 目标仍为充值后快速转出；需与 CA 确认能否用现有规则实现、是否需要组合规则。
5. RL_0020 的逻辑写 730 calendar_days，但问题描述仍提 30 天，存在资料内冲突；该规则不在本期启用范围，不自行选取其一。

## 4. 主流程

1. 平台接收到本期范围内的成功交易事件，持久化交易归属、业务类型、事件类型、金额和原业务标识。
2. 生成监控上送任务，保留业务成功状态与上送状态，两者独立。
3. CA 接收并评估交易。受理成功不表示无风险，也不保证已形成案件；告警／案件回传方式、延迟和取回机制待接口契约确认。
4. 按上游稳定标识接收或更新案件，关联客户、命中规则与交易；重复回传不重复建案。多规则聚合、多笔交易关联方式不可只按客户自行合并。
5. 运营领取案件、查看命中原因及交易、记录调查过程，提交结论。
6. 负责人提交“接受并结案”或“升级至 CA”，附调查说明；CA 确认后才更新阶段和提交记录。升级后本平台只读，后续处理在 CA 完成。失败保留原阶段、说明和请求，核查后再重试。

## 5. 页面与交互

### 5.1 案件列表

[打开案件列表](../../prototypes/交易监控/2026-11-19_案件列表_管理端.html)

- 统计条：全部案件、我的待办、已升级至 CA、已结案。我的待办只计当前负责人尚未升级或结案的案件。
- 筛选：案件号／客户 UID、业务、阶段、我的待办／待领取、负责人、规则、日期；支持重置、分页和空结果。
- 列表：Case ID、客户 UID、业务、规则、关联交易数、阶段、负责人、创建时间、查看／领取。
- 领取只分配负责人，不改变 CA 阶段；已被他人领取不能覆盖。首版仅一个运营处理角色，不开发本地审批队列或人员转派。

### 5.2 案件详情与处理

[打开案件详情](../../prototypes/交易监控/2026-11-19_案件详情_管理端.html?id=CASE-DEMO-001)

主线：领取 → 开始调查 → 接受并结案 / 升级至 CA。

| 当前状态 | 操作人 | 操作 | CA 确认后的结果 |
| --- | --- | --- | --- |
| 未开始、无负责人 | 有处理权限的运营 | 领取 | 负责人更新，阶段不变 |
| 未开始、已领取 | 当前负责人 | 开始调查 | 调查中 |
| 调查中 | 当前负责人 | 保存草稿 | 仅平台保存，阶段不变 |
| 调查中 | 当前负责人 | 接受并结案 | 已结案，保留调查说明，只读 |
| 调查中 | 当前负责人 | 升级至 CA | 已升级至 CA，保留负责人和说明，本平台只读 |
| 已升级至 CA | CA 中有权限的人员 | 在 CA 后续处理 | 平台读取实际结果，不提供本地继续处理入口 |

以上中文是产品展示语义，必须映射至账户真实工作流标识，不是自创 CA 固定枚举。`state` 的旧枚举含升级中和升级终态，不可仅凭名称当作相同阶段；用真实 `stage.identifier` 与工作流配置确定目标，未配置时不伪造成功。

- 详情展示概况、负责人、命中原因、关联交易、调查说明、处理结果、操作日志。关联交易区分触发交易与上下文交易，证据状态不当作交易业务状态。
- 只由当前负责人填写说明、保存草稿和提交；他人只读。处理结果仅“接受并结案”“升级至 CA”。说明和结果必填，提交前二次确认。
- 领取调用分配接口；开始调查及处理结果调用阶段变更接口。升级保留当前负责人，不同时调用取消分配，避免 MVP 引入多请求交接流程。CA 后续分工由其现有流程承担。
- 不提供本地合规接收、复核、退回补充、人员转派或重开。升级不是确认可疑，也不是自动结案；结案不改变交易或资金，不代表监管报送完成。
- CA 已确认才改变阶段。提交失败或结果未知，保留请求、说明和最后确认阶段；提交人先核查：已完成仅更新本地记录，确认未执行重试原请求，未知不重发。刷新后可继续核查，不永久停留在提交中。
- 原型的核查结果选择框仅演示服务端结果；正式产品由后台查询 CA 决定，不让运营猜测受理状态。真实权限、并发和重复请求防护由后端执行。
- Card 快速转出仍为拟议场景，保留时间线查看；Excel 没有确认其业务配对和阈值，样例不冒充已投产规则。

### 5.3 监控交易记录

[打开监控交易记录](../../prototypes/交易监控/2026-11-19_监控交易记录_管理端.html)

此页面覆盖所有纳入监控的交易，包括未产生案件者。

- 统计条：纳入监控、已上送、待上送、上送失败；待上送统计包含正在上送的任务。
- 筛选：客户 UID／平台交易号、业务、交易事件、CA 上送状态、成功日期；支持重置、分页。
- 列表：成功时间、平台交易号、客户 UID、业务／事件、原始金额与币种、业务状态、CA 上送状态、关联 Case、详情／补送。
- 交易详情：保留原币与折算字段、网络、CA 受理编号、补送记录；无网络概念的银行／卡交易展示“不适用”。CA 未受理或未返回编号时不得生成伪编号。
- 上送状态：待上送 → 上送中 → 已上送／上送失败。已上送仅指 CA 受理结果已确认。
- 失败补送前，按原交易标识核查受理结果。已受理：仅修正状态；确认未受理：沿用原标识补送；结果未知：保持失败并记录核查，禁止盲目新增一笔上送。
- 同一任务执行中禁止再次补送。最终幂等键、查询接口与重试策略需与 CA 确认；不得把原型的结果选择框放入正式操作流程。

## 6. 字段核对：Excel 优先，API 补缺

优先依据 `Apex Markets Inc _ Mesh TM Scoping Sheet.xlsx`；交易字段读取 `3.1 Bank_Payments_Schema`（B）、`3.2 Card_Payments_Schema`（C）、`3.4 Crypto_Payments_Schema`（X）列 D（API Field Name），规则读取 `4. Scenarios`。不混用标记 OLD 的工作表，不把 F 列 Protobuf 简写直接当 JSON 路径。下表行号均为 Excel 实际行号。

| 页面／业务字段 | Excel 中的 API 路径或口径 | 来源行 B / C / X | 展示与使用 |
| --- | --- | --- | --- |
| CA 交易标识 | `-` | 3 / 3 / 3 | H 列说明为 CA assigned tx_ID；只读保存真实返回，不生成伪编号。 |
| CA 客户内部标识 | `transaction.customer_identifier` | 4 / 4 / 4 | CA 生成、只读；不能直接填平台 UID。 |
| 资金方向 | `transaction.details.direction` | 5 / 5 / 5 | CA 计算、只读；Bank/Crypto 根据客户作为 debtor/creditor 推导，Card 根据 payment_stage 推导。 |
| 业务类型 | `transaction.details.type` | 10 / 11 / 8 | BANK_PAYMENT / CARD_PAYMENT / CRYPTO；平台业务名只作展示映射。 |
| 平台交易号 | `transaction.external_identifier` | 11 / 12 / 9 | 使用稳定外部交易标识，重试复用；平台原始字段名仍需开发映射。 |
| 客户 UID 关联 | `transaction.customer_external_identifier` | 12 / 13 / 10 | 使用与 CA 客户创建一致的外部标识映射，保留平台 UID 与 CA 内部标识关系。 |
| 交易发生时间 | `transaction.occurred_at` | 13 / 14 / 11 | 平台保留成功时间；上送发生时间按事件定义，不能把两者未经确认直接视为相同。 |
| 折算金额 | `transaction.details.base_value.amount` | 16 / 17 / 14 | Excel 标 Yes；基准币和折算来源未确认时不填零，不默认用原币代替。 |
| 折算法币币种 | `transaction.details.base_value.currency` | 20 / 21 / 18 | Conditional；加密资产另用 crypto_asset，不能把 USDT 当 ISO 法币。 |
| 原币金额 | `transaction.details.local_value.amount` | 21 / 22 / 19 | Conditional；按 Excel local_value 保留，页面原业务金额不得丢失。 |
| 原币法币币种 | `transaction.details.local_value.currency` | 25 / 26 / 23 | Conditional；加密币保留 local_value.crypto_asset 标识与 symbol，不假造法币代码。 |
| 链网络 | `transaction.details.chain.network_name`、`network_type` | — / — / 113–114 | X113 可选名称，X114 必填类型；Bank/Card 显示不适用。 |
| 原币加密资产 | `transaction.details.local_value.crypto_asset.identifier.namespace`、`reference`、`symbol` | 22–24 / 23–25 / 20–22 | 标识按条件提供，symbol 仅展示，不能取代资产唯一标识。 |
| 折算加密资产 | `transaction.details.base_value.crypto_asset.identifier.namespace`、`reference`、`symbol` | 17–19 / 18–20 / 15–17 | 与法币 currency 按资产口径选用，不把 USD 与 USDT 混同。 |
| 规则编号、名称、方向、阈值、优先级 | `4. Scenarios` 第 8–21 行 | 规则表 | RL_0013–0018；7 calendar_days、>3、>100,000、Allow、P7 - Low 依表保留；未确认生产启用。 |
| 统计对象 | `{customer_identifier.id, type}` | 规则表第 10–21 行 | 这是规则引擎表达式；不能用平台 UID 直接替代 CA 内部客户标识，也不跨类型汇总。 |

规则阈值来自 Excel 配置；命中实际值、准确窗口起止应来自命中当时的上游证据。不能用当前关联交易条数或自行减 7 天替代真实命中快照。原型数值明确为虚构样例，未提供真实值时显示“暂未获取”。

Excel 未定义案件操作与风险查询返回，以下补充依据 Mesh API OpenAPI v2.0（服务地址 `https://api.mesh.complyadvantage.com`，本次核对本地保存的 `ca-openapi.json`，未验证在线最新版本）。

| 页面字段／动作 | 补充 API 来源 | 映射与缺失处理 |
| --- | --- | --- |
| 案件号、创建时间、阶段、负责人 | GET `/v2/cases/{case_identifier}`：`identifier`、`created_at`、`stage`、`assignee` | 显示 `stage.display_name`，使用 `stage.identifier`；`assignee` 为空显示未分配，非空需 CA 用户映射，不能发中文姓名。 |
| 领取 | POST `/v2/cases/{case_identifier}/assign`：`assignee` | 与阶段变更独立；只分配当前有效 CA 用户标识。 |
| 开始调查、接受并结案、升级 | POST `/v2/cases/{case_identifier}/transition`：`stage_identifier`、`note` | 使用真实工作流目标；不使用已废弃 state 写法。note 文档上限 5000；产品要求处理结论必填说明，接口约束写需求、原型不实现长度校验。 |
| 调查记录 | GET/POST `/v2/cases/{case_identifier}/notes`：`contents`、`created_at`、`created_by`、`type` | 单独新增说明用 contents（上限 5000）；阶段提交附带 note，不再重复新增同一份说明。保存草稿仅平台本地。 |
| 告警与风险关联 | GET `/v2/cases/{case_identifier}/alerts`；GET `/v2/alerts/{alert_identifier}/risks` | 从案件关联告警再取风险，不能只按客户拼案，不能用 RL 编号冒充风险标识。 |
| 命中说明 | GET `/v2/transaction-monitoring/risks/{risk_identifier}`；`transaction_ScenarioObservationResponse.configuration/observation` | 按实际返回解释风险；不假造统一 actual/threshold/window 响应字段，缺值展示暂未获取。 |
| 关联交易、关联类型、证据状态 | GET `/v2/transaction-monitoring/alerts/{alert_identifier}/related-transactions`：`related_transactions[].identifier/type/status/version/occurred_at` | type 为 ALERTING / CONTEXTUAL；status 为 UP_TO_DATE / UPDATED / OUTDATED，不是业务成功状态。取回所有分页后统计去重交易数。 |
| 评估结果 | `ol_EvaluationResultDTO.outcome`、`scenario_evaluations` | 受理成功不代表评估完成；ALLOW 不证明没有案件，不能触发资金放行。 |
| 按外部交易标识核查 | GET `/v3/transactions/external/{identifier}` | 用原外部交易标识核查，返回未完成或未知时不盲补；生产幂等及一致性窗口仍需联调。 |
| 工作流映射 | GET `/v2/cases/workflows` 及 workflow/version 详情 | 取实际配置确定目标 stage_identifier，不能硬编码演示中文状态。 |

平台自有字段：业务事件、成功状态／成功时间、CA 上送任务状态、补送次数、调查草稿、操作提交状态、平台操作日志、客户 UID 均由平台数据或任务计算，不声称 CA 提供同名字段。处理结论保留平台提交值，并用 CA 阶段及记录核对；后续在 CA 完成的结果读取真实返回，不凭旧本地结论覆盖。

核对边界：Excel 的类型、路径、方向和规则已逐项核对；平台数据源到 Excel 空白 Inbound/Outbound 栏的具体字段名、基准币、实际账户阶段及 Card 充值／转 Wallet 的 payment_stage 尚需联调确认。未确认项不填推测值。

## 7. 权限、异常与审计

- 查看权限与处理权限分开；所有查询、领取、草稿、提交和补送必须后端授权，前端隐藏按钮不能代替校验。
- 负责人校验及提交需支持并发冲突处理；重复请求不得重复结案、重复新增结论或重复计数。
- 审计至少记录案件领取、草稿保存、结论提交、同步尝试／结果、受理核查／补送及操作者。敏感凭据、完整鉴权头不进入界面或日志。
- 案件不存在／无权访问按系统规范提示；上游失败、网络错误、空数据分别处理。
- 业务成功与监控故障解耦；监控失败不得回写原交易为失败，也不自动冲正资金。
- 生产告警、重试间隔、最大重试次数、记录保留期限与服务目标待确认，不用演示延迟代替 SLA。

## 8. 验收标准

| 编号 | 验收场景 | 预期 |
| --- | --- | --- |
| A1 | Crypto 失败或处理中交易、USD／Bridge VA、Card 消费进入事件源 | 不被本期成功交易监控误纳入 |
| A2 | 同一客户同时有 Bank 与 Crypto 入金 | 各 type 独立统计，不跨业务拼成笔数／金额告警 |
| A3 | 存在不同原币交易 | 原币分别展示；没有确认的折算依据不直接合计 |
| A4 | 按业务、状态、客户和日期查案件／交易 | 查询和分页正确，无结果明确展示；日期区间错误提示修正 |
| A5 | 两个运营并发领取 | 只有一个成功；另一方得到冲突反馈，归属不覆盖 |
| A6 | 负责人保存调查草稿后重新进入 | 草稿仍在；非负责人不能修改 |
| A7 | 缺调查说明或未选结论提交 | 阻止提交；完整提交只产生一份处理记录 |
| A8 | 提交结案失败或结果未知 | 保留最后确认的阶段及负责人，保留草稿与请求；核查后恢复，不重复记录，不影响交易状态 |
| A9 | 上送超时，CA 实际已受理 | 核查后修正状态，不重复上送或重复统计 |
| A10 | 确认 CA 未受理后补送 | 原标识复用，交易记录总数不增加；未知结果不盲补 |
| A11 | Card 转 Wallet | 不重复产生链上入金；时间线保留原始币种，不伪造资金配对 |
| A12 | 结案／升级至 CA | 不出现放行／拒绝／冻结资金动作 |
| A13 | 领取后未开始调查 | 负责人更新，阶段仍未开始；开始调查单独提交 |
| A14 | 升级至 CA | 保留调查记录，本地只读，没有接收／复核／退回／转派按钮 |
| A15 | 提交时刷新或断网 | 重新打开可核查原请求，不能永久停留提交中 |
| A16 | 核查已完成、未执行、未知 | 分别更新本地、重试原请求、保持待核查；不重复新增记录 |
| A17 | 非负责人查看 | 调查表单只读，不能提交 |
| A18 | Excel/API 来源核对 | 保留字段标明来源，平台字段与 CA 字段分开，未确认值不伪造 |


原型已覆盖列表、详情、时间线、领取、草稿、提交、同步失败重试及补送的浏览器演示。A1–A3、A5 等生产接入／并发标准需在真实服务联调验收，不能凭本地演示宣称通过。

## 9. 决策与待确认项

| 编号 | 状态 | 决策／问题 | 影响 |
| --- | --- | --- | --- |
| D1 | 沿用确认 | 本期范围见第 2 节；成功交易事后监控 | 不增加预交易拦截 |

| N6 | 旧多级流程已作废；接入待验证 | 按 MVP 单角色处理，升级后交 CA；平台不提供复核与转派 | 核验 CA 用户、真实阶段与升级后处理职责 |
