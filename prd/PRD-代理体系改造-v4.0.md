## 1. 产品概述

### 1.1 背景（As-Is 问题）

现行代理体系存在三个结构性问题：

1. **代理身份零门槛沉淀**：用户注册即默认获得「积分代理」身份，导致代理池中大量无效代理，稀释了代理身份的稀缺性与运营价值。
2. **开通路径黑箱**：卡片代理（返 U）需后台手动开启，用户端无感知、无申请入口，代理资格获取依赖人工判断与线下关系，不可规模化。
3. **返佣颗粒度粗**：返 U 比例只能全局统一或按单人统一配置，无法按卡产品差异化，导致线下商务谈判达成的差异化方案无法落到系统，只能"记在纸上"。

### 1.2 目标

| 目标 | 衡量口径 | 目标值 |
|---|---|---|
| 提高代理门槛，清理无效代理 | 代理申请通过率 | ≤ 40%（首季度） |
| 开通流程线上化、可追溯 | 申请至开通的平均时长 | ≤ 3 个工作日 |
| 返佣配置细化到卡级别 | 支持差异化配置的卡产品覆盖率 | 100% |
| 线下谈判结果系统留痕 | 返佣比例变更的可审计率 | 100% |

### 1.3 范围

**本期包含**

- 客户端：代理申请入口、协议签署、申请状态流转、代理中心（推广链接 + Points/USDT 返佣记录）
- 管理端：代理管理（含「申请中」Tab）、代理审核与按卡返佣配置、平台默认返佣比例（兜底）、返佣配置操作日志
- B 端：代理推广与收益看板（按卡维度重做）
- 存量代理用户的平滑过渡规则

**本期不包含**

- 多级分销（二级及以上）返佣
- 代理结算打款通道改造（沿用现行结算流程）
- 代理推广素材库 / 落地页生成器
- 代理等级体系（分级代理、升级降级规则）

## 3. 业务模型总览

### 3.1 As-Is → To-Be 对比

| 维度 | 当前逻辑（As-Is） | 新逻辑（To-Be） | 核心变化 |
|---|---|---|---|
| 初始身份 | 注册即默认获得「积分代理」身份 | 注册为普通用户，无代理身份 | 提高门槛，避免无效代理沉淀 |
| 开通方式 | 积分代理默认开通；卡片代理（返 U）后台手动开启 | 客户端「代理中心」主动签署协议申请，后台承接审核 | 新增「协议签署」环节，合规前置 |
| 返佣配置（返 U） | 后台全局或按单人统一配置 | 按卡产品分别设置开卡返佣、充值返佣比例 | 颗粒度细化到卡级别，支持差异化谈判 |
| 返佣配置（Points） | 后台统一配置 | 后台统一配置（保持不变） | 统一标准，与返 U 差异化形成对比 |
| 业务流转 | 线上自动生效积分流 → 线下人工开启返 U | 线上申请 → 线下商务洽谈 → 线上差异化配置生效 | 强化线下 BD 环节并系统留痕 |

### 3.2 代理状态机

```
                    ┌─（商务审核拒绝）─→ 已拒绝 ──（重新申请，满足冷却期）──┐
                    │                                                      │
普通用户 ──（签署协议并提交）──→ 申请中 ──（审核通过 + 配置返佣）──→ 已开通 ──（运营停用）──→ 已停用
                    │                                                      │
                    └─（用户撤回）─→ 无代理身份 ←──────────────────────────┘（退出计划）
```

| 状态 | 客户端可见文案 | 后台可操作 | 是否产生返佣 |
|---|---|---|---|
| 普通用户 | 展示申请入口 | — | 否 |
| 申请中 | 「代理资格申请中，请等待商务经理联系」 | 审核 / 配置 / 拒绝 | 否 |
| 已开通 | 解锁代理中心与看板 | 返佣配置 / 停用 | 是 |
| 已拒绝 | 展示拒绝原因 + 重新申请入口 | 查看原因 | 否 |
| 已停用 | 展示停用提示 | 恢复 / 查看历史 | 否（历史待结算部分按约定结算） |

### 3.3 返佣优先级

```
代理专属按卡配置（单独配置）  >  平台默认比例（全局兜底）
```

## 5. 功能需求

### 5.1 客户端：代理申请入口 `F-101`

**用户故事**：作为普通用户，我希望在奖励模块看到申请成为代理的入口与权益说明，以便判断是否申请。

| 项 | 说明 |
|---|---|
| 位置 | 客户端 Rewards 模块 → 代理中心 |
| 前置条件 | 用户已完成实名认证（KYB） |
| 页面元素 | ① 状态标识（当前身份：普通用户）② Hero 引导卡：标题 + 说明 + 主 CTA「申请成为代理」+ 次 CTA「阅读代理协议」③ 权益三卡（开卡返佣 / 充值返佣 / Points 返点）④ 开通流程四步 ⑤ 返佣计算口径示例表（比例列展示「待商务确定」）⑥ 底部口径说明 |
| 交互 | 点击「申请成为代理」→ 跳转协议签署页（F-102） |
| 业务规则 | BR-101：未完成实名认证时，CTA 置灰并提示「请先完成实名认证」<br>BR-102：已提交申请的用户进入本页自动跳转申请状态页（F-103），不重复展示入口<br>BR-103：入口页不展示任何具体返佣比例数值，避免构成对用户的收益承诺 |
| 异常 | EX-101：实名认证状态查询失败 → CTA 置灰 + 提示重试，不阻塞浏览权益说明 |

### 5.3 客户端：代理申请状态 `F-103`

**用户故事**：作为已提交申请的用户，我希望随时了解申请进度与下一步动作。

## 6. 异常与边界规则

### A-1 存量历史用户平滑过渡（重点）

| 方案 | 规则 | 优点 | 风险 |
|---|---|---|---|
| **方案 A（推荐）** | 存量已有邀请关系（下级归属）的用户，系统自动标记为「已签署协议」，继承现有代理权限与分润关系 | 用户体验平滑，无需打扰老代理 | 合规瑕疵：缺失真实签署记录 |
| 方案 B | 系统强控拦截：老用户进入奖励模块须补签协议，补签完成后历史上下级关系与分润继续生效 | 合规闭环完整 | 未补签期间返佣暂停，可能引发客诉 |

**建议**：采用 **A + B 混合**——先按方案 A 自动打标放行以保障业务连续性；同时在客户端展示补签提示条，要求存量代理在 **30 个自然日内**补签协议，逾期暂停返佣结算。补签记录与自动打标记录须分别留痕，便于合规审计。

> 决策点 → 见附录 B-3。

### A-2 积分与返佣生效节点

- 代理身份、Points 返点与 USDT 返佣权限**同时解锁**，均以「后台审核通过并完成配置」为生效节点。
- 审核期间产生的下级业务**不追溯返佣**（生效前的业务不计入）。

### A-3 卡片停发 / 新增卡种联动

- 平台提供「默认返佣比例（全局兜底）」配置项；新增卡产品上线时，老代理默认自动应用兜底比例。
- 停发卡产品不再产生新返佣，历史记录保留可查。
- 需差异化对待的代理，通过 F-202 单独配置覆盖。

### A-4 线下转线上操作防错

- 按卡配置返佣比例时**强制写入操作日志**（F-205）：操作人、修改时间、修改前 / 修改后比例、来源 IP。
- 单次提交修改多项时共享批次号，支持按批次追溯一次线下沟通达成的整体方案。
- 日志支持导出，作为商务与代理对账、处理客诉的凭证。

### A-5 其他边界

| 编号 | 场景 | 处理 |
|---|---|---|
| E-01 | 同一客户被多个代理推广 | 以首次有效归因（首点归属）为准，其余不重复计佣 |
| E-02 | 代理自邀（自己开卡给自己返佣） | 系统识别同人/同设备/同支付工具，不予计佣并标记风险 |
| E-03 | 客户开卡后退卡 | 触发 Clawback，追回开卡返佣与双方 Points 返点 |
| E-04 | 代理被停用期间下级仍有业务 | 不产生新返佣；停用前已产生未结算部分按约定结算 |
| E-05 | 协议版本升级 | 已开通代理须在下次登录时签署新版协议；未签署前保留原权限 30 天，逾期暂停结算 |

## 7. 非功能需求

### 8.1 核心实体

| 平台默认比例 `platform_rebate_default` | `card_product_id`(可空=全局)、`opening_rebate_usd`、`recharge_rebate_pct`、`auto_apply_new_card` |

### 8.2 关键一致性约束

- `rebate_transaction.rebate_source` 必须与计提时 `agent_card_rebate` 或 `platform_rebate_default` 的实际命中项一致，且**快照留存**（后续比例变更不影响历史记录）。
- `agent_application.signed_at` 为空的用户不得进入「已开通」状态（方案 A 自动打标用户除外，须以 `legacy_auto_marked=true` 单独标记）。
