# YASBE 管理端 — Card 模块账务功能 PRD

## v2.0 — 2026-06-02

---

## 1. 产品概述

### 1.1 背景与目标

YASBE 管理后台（admin.beeznis.com）的 Card 模块已实现卡片生命周期管理（列表、详情、状态变更、限额管理）和基础交易记录展示。但**财务/账务层面的管理能力**目前缺失：

- 卡片费用结算记录不可查
- 平台侧费用账单无独立管理入口
- 争议工单缺乏系统化管理
- 财务数据没有汇总看板

**目标**：构建 YASBE 平台自身的 Card 模块账务体系，使运营和财务人员能够一站式管理卡片相关的费用、账单、争议和财务分析。

### 1.2 范围

- **平台**：YASBE 管理后台 Web 端（React 18 + Ant Design）
- **目标用户**：
  - 财务人员：费用结算、账单核对
  - 运营人员：争议处理、退款操作
  - 管理员：财务看板监控
- **定位**：Card 模块下的增补功能（新增侧边栏子菜单）
- **说明**：本版本仅聚焦 YASBE 平台自身的账务数据管理。与 Interlace 等渠道方的对账由财务自行线下核对，不在本版本范围内。

### 1.3 模块概览

| 子模块 | 说明 | 优先级 |
|--------|------|--------|
| 费用结算（Settlement） | 平台侧卡片费用明细及结算记录 | P1 |
| 账单管理（Billing） | 平台侧月度费用账单查询 | P1 |
| 争议与退款（Dispute & Refund） | 争议工单 + 退款申请管理 | P1 |
| 财务看板（Dashboard） | 多维财务数据概览 | P2 |

### 1.4 术语表

| 术语 | 含义 |
|------|------|
| Settlement | 结算：按周期汇总的平台卡片费用记录 |
| Opening Fee | 开卡固定费用 |
| Recharge Fee | 充值手续费 |
| Consumption Fee | 消费手续费 |
| First Open Discount | 首次开卡优惠减免 |
| Rebate Rate | 返佣比例：用户消费/充值相关行为触发，平台向用户发放 YASBee 代币的激励比例。不属于平台费用收入，以 YASBee 数量计算 |
| YASBee | YASBE 平台发行的代币 |

## 3. 功能需求

### 3.1 费用结算模块（F-AC-001 ~ F-AC-004）

#### 3.1.1 费用结算列表（F-AC-001）

| 字段 | 值 |
|------|-----|
| **优先级** | P1 |
| **用户故事** | 作为财务人员，我希望按维度查看全平台卡片产生的各项费用，以便了解平台费用构成 |
| **功能描述** | 费用结算列表，按结算周期（日/月）或单卡维度展示费用汇总 |

**费用类型枚举**（按 YASBE 平台实际卡产品配置）：

| 费用类型 | 说明 | 单位 |
|---------|------|------|
| Opening Fee | 开卡费 | USD |
| Recharge Fee | 充值手续费 | USD |
| Consumption Fee | 消费手续费 | USD |
| First Open Discount | 首次开卡优惠 | USD |

> 注：开卡费支持 USDT/USDC 等稳定币支付；充值费和消费费也支持多种币种发起，结算时统一按 USD 记账。

**返佣说明**：Rebate（返佣）不属于平台费用类型。返佣是平台根据用户消费/充值行为，按 **Rebate Rate** 计算向用户发放 **YASBee 代币** 的激励措施。结算列表和账单中单独展示返佣代币发放量（单位：YASBee），不计入费用总计。

**结算列表字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| 结算编号 | string | SET-YYYYMMDD-xxx |
| 结算周期 | string | 日 / 月 |
| 结算日期 | date | 2026-06-01 |
| 卡片总数 | int | 参与结算的卡片数 |
| 开卡费合计 | decimal | Opening Fee 总和（USD） |
| 充值费合计 | decimal | Recharge Fee 总和（USD） |
| 消费费合计 | decimal | Consumption Fee 总和（USD） |
| 首次优惠合计 | decimal | First Open Discount 总额（USD，负值：优惠支出） |
| **费用总计** | decimal | 以上开卡+充值+消费+首次优惠总和 |
| 返佣发放量 | decimal | 本月 Rebate Rate 对应 YASBee 代币发放量（不计入费用） |
| 状态 | enum | PENDING / SETTLED |

**状态流转**：
```
PENDING（待结算）→ SETTLED（已结算）
```

**功能规格表**：

| 功能 | 需求描述 | 优先级 | 验收标准 |
|------|---------|:------:|---------|
| 结算列表 | 按结算日期倒序展示所有结算记录 | P1 | AC-AC-001 |
| 筛选 | 按结算周期（日/月）、状态、日期范围筛选 | P1 | AC-AC-002 |
| 结算详情 | 点击结算行展开详情（参与卡片列表及每张卡的费用明细） | P1 | AC-AC-003 |
| 导出 CSV | 导出当前结算报告 | P2 | AC-AC-004 |

#### 3.3.3 退款管理（F-AC-023）

| 类型 | 说明 | 触发 |

| 字段 | 类型 | 说明 |
|------|------|------|
| 退款编号 | string | RF-YYYYMMDD-xxxxx |
| 卡片后4位 | string | — |
| 用户 UID | string | — |
| 退款金额 | decimal | USD，须 ≤ 卡片当前余额 |
| 退款类型 | enum | 见上表 |
| 原因 | string | 必填 |
| 审批状态 | enum | PENDING / APPROVED / REJECTED / COMPLETED / FAILED |
| 发起人/时间 | string/datetime | — |
| 审批人/时间 | string/datetime | — |

**审批路由规则**：

| 金额范围 | 审批层级 | 审批人 |
|---------|---------|--------|
| ≤ $100 | 一级 | 运营主管 |
| > $100 | 二级 | 运营主管 + 风控/管理员 |

**退款执行**：
- 审批通过 → 调用退款 API
- 执行成功 → 卡片余额实时更新
- 执行失败（如余额不足）→ 标记 FAILED，通知审批人

**功能规格表**：

| 功能 | 需求描述 | 优先级 | 验收标准 |
|------|---------|:------:|---------|

| 审批流 | 按金额自动路由到对应审批层级 | P1 | AC-AC-032 |
| 退款执行 | 审批通过后自动执行退款 | P1 | AC-AC-033 |
| 退款历史列表 | 展示全部退款记录 | P1 | AC-AC-034 |
| 退款失败处理 | 失败状态标记 + 通知 | P1 | AC-AC-035 |

### 5.1 新增数据表/接口规划

| 模块 | 建议数据表 | 主要字段 | 数据来源 |
|------|-----------|---------|---------|
| 费用结算 | `card_settlement` | 结算编号/周期/日期/开卡费/充值费/消费费/首次优惠/返佣发放量/状态 | 平台内部计算 |
| 费用明细 | `card_settlement_detail` | 结算ID/卡片ID/费用类型(枚举4种)/金额/币种(USD) | 逐卡计算 |
| 返佣发放 | `card_rebate` | 结算ID/卡片ID/用户UID/触发行为/消费金额/返佣比例(Reabte Rate)/发放YASBee数量 | 平台计算 |
| 账单管理 | `card_bill` | 账单编号/月份/开卡费/充值费/消费费/首次优惠/净收入/返佣发放量/状态 | 费用结算月度聚合 |
| 争议工单 | `card_dispute` | 工单编号/用户/卡片/交易/金额/类型/状态/处理结果/处理人 | 运营创建 |
| 退款申请 | `card_refund` | 退款编号/卡片/金额/类型/审批状态 | 运营发起 |

**数据流**：

```text
开卡记录 → Opening Fee
充值记录 → Recharge Fee  \                                                → 费用结算 → 月度账单
消费记录 → Consumption Fee /                              ↘                ↘
消费/充值行为 → Rebate Rate  → 返佣发放（YASBee 代币）        争议工单 → 处理追踪    财务看板
                                                                  ↓
                                                            退款申请 → 审批流 → 执行
```
