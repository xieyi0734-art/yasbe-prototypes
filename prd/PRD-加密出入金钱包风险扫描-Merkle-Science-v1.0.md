## 1. 产品概述

### 1.1 背景
YASBee 平台现有加密出入金能力（客户端 Crypto 交易模块 + 管理端「加密货币」节点）。当前出入金在链上确认后直接入账 / 出金，缺乏对**对方钱包**的合规风险筛查。为满足反洗钱（AML）与制裁合规要求，需引入 Merkle Science 钱包/交易风险扫描能力。

### 1.2 目标
- 在入账 / 出账动作**之前**，对「对方钱包」执行 Merkle Science 风险扫描。
- 命中风险告警的订单**不自动入账 / 不自动出金**，统一进入 `pending` 由运营人工审核。
- 入金拒绝 → **原路退款**；出金拒绝 → **出金失败**。
- 审核动作全量留痕，并与 Merkle 告警处理结果（resolve）保持同步。

### 1.3 范围
**In-scope**
- 加密入金发送方钱包扫描 + 风险告警 + 人工审核（批准入账 / 拒绝退款）。
- 加密出金接收方钱包扫描 + 风险告警 + 人工审核（批准放行 / 拒绝出金失败）。
- 管理端「加密货币 → 交易审核」风险审核队列 + 审核详情（Merkle 风险明细）。
- 客户端交易记录新增风险相关状态展示（Pending Review / Refunded / Failed）与合规提示。
- 风险阈值 / 告警等级 → 处置策略的可配置能力（风控规则）。

**Out-of-scope（本期不做）**
- 客户级跨链风险聚合画像（`POST /customers/`）—— 后续增强。
- 已入账 / 已出金交易的持续监控重审（Webhook 二次拦截）—— 后续增强，见 F-011。
- Merkle 合规报告（PDF）在线导出 —— 后续增强。

### 1.4 术语
| 术语 | 定义 |
|---|---|
| 对方钱包 | 入金时的**发送方钱包**；出金时的**接收方（目的）钱包** |
| 风险告警 | Merkle Science 返回的 `risk_level ≥ 阈值` 时产生的命中记录 |
| Pending Review | 风控命中、等待人工审核的订单状态（对应平台 `PENDING`） |
| 原路退款 | 入金被拒后，资金退回来源钱包（或转入挂账待处理） |
| 出金失败 | 出金被拒后，资金解冻退回用户可用余额，订单终态 `FAILED` |

## 3. 功能需求

> 功能点编号 F-XXX。每个功能含 优先级 / 用户故事 / 业务规则 / 异常流程 / 字段定义 / UI 说明 / API。

### F-001 入金发送方钱包风险扫描
- **优先级**：P0（Must）
- **用户故事**：作为平台，当一笔加密入金交易在链上确认后，我要在入账前扫描发送方钱包，命中风险则不自动入账。
- **业务规则**：
  - 触发时机：链上交易确认后、入账动作之前。
  - 调用 Merkle `POST /api/v4/transactions/`，`type=1`（Deposit），仅筛发送方。
  - `risk_level ≥ 阈值`（默认 `3`，可配置）→ 订单置 `PENDING`，生成风险告警，通知运营；否则自动入账 `COMPLETED`。
  - 地址格式非法 → 直接拒绝，不送 Merkle。
- **异常流程**：
  - Merkle 超时 / 5xx → fail-closed：进 `PENDING`，标记「风控待人工复核」（见 F-012）。
  - 筛查返回但无告警 → 正常入账。
- **字段定义**：见附录 A（交易筛查入参/出参）。
- **UI 说明**：客户端交易记录对应订单显示 `Pending Review`；管理端进入入金风险队列。
- **API**：`POST /transactions/`（type=1）。

### F-002 出金接收方钱包风险扫描
- **优先级**：P0（Must）
- **用户故事**：作为平台，当用户提交加密出金（含 2FA 校验通过）后，我要在出账前扫描接收方钱包，命中风险则暂缓出金。
- **业务规则**：
  - 触发时机：用户出金提交（2FA 通过）后、链上广播之前。
  - 调用 Merkle `POST /api/v4/addresses/`，`type=2`（Withdrawal），筛接收方。
  - `risk_level ≥ 阈值` → 订单 `PENDING`，生成风险告警，通知运营；否则提交链上出金。
- **异常流程**：同 F-001，超时 fail-closed 进 `PENDING`。
- **字段定义**：见附录 A（地址筛查入参/出参）。
- **UI 说明**：客户端交易记录对应订单显示 `Pending Review`；管理端进入出金风险队列。
- **API**：`POST /addresses/`（type=2）。

### F-003 风险告警生成与订单状态机
- **优先级**：P0（Must）
- **用户故事**：作为系统，我要在风险命中时生成告警、驱动订单状态流转，并保证资金不提前入账/出账。
- **业务规则**：见 §7 状态机。
- **字段定义**：告警含 `identifier`（地址/交易哈希）、`risk_level`、`type`、`status`、`level`、`blockchain`、`customer_id`。

### F-004 管理端风险审核队列
- **优先级**：P0（Must）
- **用户故事**：作为运营，我要在「加密货币 → 交易审核」看到入金 / 出金两条待审队列，按风险等级与时间排序。
- **业务规则**：
  - 两条队列：入金风控命中队列、出金风控命中队列。
  - 队列列：交易 ID / 客户 / 币种·链 / 金额 / 对方钱包 / 风险等级 / 命中摘要 / 提交时间 / 操作。
  - 严重风险 / 高风险优先展示；队列可筛选（风险等级、币种、客户）。
  - 审批后自动移出队列，可在「交易记录」查看历史。
- **异常流程**：无告警但进队（fail-closed 单）在「命中摘要」列标记「风控服务超时 · 人工复核」。
- **UI 说明**：沿用「法币管理 → 交易审核」三队列模式；统计栏含 待审入金 / 待审出金 / 高风险·严重风险 / 今日已审核。

### F-005 风险审核详情（Merkle 风险明细）
- **优先级**：P0（Must）
- **用户故事**：作为运营，我要在审核详情里看到 Merkle 风险等级、命中告警明细（类别/匹配详情/置信度/直接或间接来源）、筛查对象与交易详情，据此判断。
- **业务规则**：
  - 展示 `risk_level` + `risk_level_verbose`；风险 banner 按等级着色（严重/高=红、中=黄）。
  - 命中告警明细列出每条告警的 风险类别 / 匹配详情 / 置信度 / 来源（直接/间接）。
  - 展示资金状态（挂账待处理 — 未计入可用余额）与处置路径。
- **UI 说明**：审核弹窗，含「Merkle Science 风险扫描结果」「命中告警明细」「资金状态」「Transaction Details」四块。

### F-006 入金审核处置（批准入账 / 拒绝退款）
- **优先级**：P0（Must）
- **用户故事**：作为运营，我要批准入账或拒绝并退款，且拒绝必须填写理由。
- **业务规则**：
  - 批准 → 解除挂账，入账 `COMPLETED`；回写 Merkle `POST /alerts/resolve/`。
  - 拒绝 → 原路退款 `REFUNDED`；必须填拒绝理由；回写 Merkle resolve。
  - 拒绝理由记入审核日志（操作人 / 时间 / 理由 / 结果）。
- **异常流程**：退款路径失败 → 挂账异常队列，人工介入（见 F-011 后续）。

### F-007 出金审核处置（批准放行 / 拒绝出金失败）
- **优先级**：P0（Must）
- **用户故事**：作为运营，我要批准放行出金或拒绝使出金失败，且拒绝必须填写理由。
- **业务规则**：
  - 批准 → 提交链上出金（`PROCESSING` → `COMPLETED`）；回写 Merkle resolve。
  - 拒绝 → 出金失败 `FAILED`，资金解冻退回用户可用余额；必须填拒绝理由；回写 Merkle resolve。
  - 出金拒绝后**不可自动重试放行**，用户需重新发起。

### F-008 审核留痕与 Merkle resolve 回写
- **优先级**：P0（Must）
- **用户故事**：作为合规，我要全量追溯每一单的审核记录，并与 Merkle 结果一致。
- **业务规则**：
  - 记录 审核人 / 审核时间 / 动作（批准/拒绝）/ 理由 / Merkle 告警 ID / 回写结果。
  - 批准/拒绝均调用 `POST /alerts/resolve/`；回写失败重试（指数退避），最终失败进待补回写队列。

### F-009 风险阈值与告警等级配置
- **优先级**：P1（Should）
- **用户故事**：作为合规，我要配置「哪些风险等级拦截进 pending」。
- **业务规则**：
  - 阈值默认 `risk_level ≥ 3（Medium）`；`Caution（2）` 是否拦截可配置；`Info（1）/ 0` 自动放行。
  - 高风险/严重风险可配置为「优先审核」。
- **UI 说明**：落「风险管理 → 风控规则管理」，新增 Merkle 风险阈值配置。

### F-010 客户端状态展示与合规提示
- **优先级**：P0（Must）
- **用户故事**：作为客户，我要在交易记录看到订单处于审核中 / 已退款 / 失败，并得到合规解释。
- **业务规则**：
  - 新增状态：`Pending Review`（审核中）、`Refunded`（已退款）、`Failed`（出金失败）。
  - **不向客户端暴露具体风险等级 / 命中原因**（防恶意方试探）。
  - `Pending Review` 详情显示通用文案「合规审核中，资金暂存，无需操作」。
- **UI 说明**：客户端 Crypto 交易记录表新增 `Counterparty Wallet` 列与状态徽章；顶部合规提示条。

### F-011 持续监控重审（Webhook，后续增强）
- **优先级**：P2（Could，本期不做）
- **业务规则**：订阅 Merkle Webhook，已入账/已出金订单风险升级时二次拦截 + 冻结 + 重审；校验 `X-WEBHOOK-KEY`。

### F-012 超时兜底与降级（fail-closed）
- **优先级**：P0（Must）
- **用户故事**：作为系统，我要在 Merkle 超时/不可用时安全降级，不放过风险单。
- **业务规则**：
  - 筛查超时（建议 ≤ 3s）或 5xx → 订单 `PENDING`，标记「风控服务异常 · 人工复核」。
  - 配额告警（接近限流）→ 熔断进入队列，避免打满 100/min。
  - 恢复后自动补扫，补扫结果若为无风险可自动放行（需保留原 pending 痕迹）。

## 7. 状态机

### 7.1 入金订单
```
链上确认 → [扫描] → 无风险 → COMPLETED（入账）
                  → 命中/超时 → PENDING（挂账待审核）
                       → 批准 → COMPLETED
                       → 拒绝 → REFUNDED（原路退款）
```

### 7.2 出金订单
```
用户提交(2FA) → [扫描] → 无风险 → PROCESSING → COMPLETED
                        → 命中/超时 → PENDING（暂缓出金）
                             → 批准 → PROCESSING → COMPLETED
                             → 拒绝 → FAILED（资金退回可用余额）
```

### 7.3 告警状态（映射 Merkle alert status）
| 平台状态 | Merkle 状态 | 说明 |
|---|---|---|
| PENDING | open | 待审核 |
| 审核中 | — | 运营打开详情 |
| COMPLETED / REFUNDED / FAILED | resolved | 审核后回写 resolve |

## 8. 验收标准

- 入金命中风险（`risk_level ≥ 阈值`）不自动入账，进入 `PENDING`，资金不计入可用余额。
- 出金命中风险不自动广播，进入 `PENDING`。
- 运营批准入账 → 订单 `COMPLETED`；拒绝 → `REFUNDED` 且理由必填留痕。
- 运营批准出金 → 放行；拒绝 → `FAILED` 且资金退回可用余额，理由必填留痕。
- 管理端两条队列（入金/出金）正确展示风险等级、命中摘要，详情展示 Merkle 告警明细与置信度。
- 客户端交易记录正确展示 `Pending Review / Refunded / Failed`，不泄露风险明细。
- 审核动作均回写 Merkle `resolve`，日志完整可追溯。
- Merkle 超时 / 5xx 时订单安全进入 `PENDING`（fail-closed），无风险漏放。
- 风险阈值可在风控规则配置，默认 `risk_level ≥ 3`。
