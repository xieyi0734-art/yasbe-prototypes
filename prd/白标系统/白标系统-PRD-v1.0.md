## 1. 背景与目标

### 1.1 业务背景

平台具备卡白标与法币 VA 的业务能力（Partner API + 开发者门户），但整条链路缺两侧的承载体：

- **租户侧缺业务台**：租户拿不到可视化的终端用户 / VA / 流水 / 账单 / 密钥载体，日常靠对接人来回沟通。
- **平台侧缺管理端**：租户准入靠线下表格、费率靠人工邮件、品牌与域名靠工程临时改配置，缺少统一的管理载体。
- **资金口径散**：手续费归谁承担、开 VA 收多少钱、欠费怎么处置，没有一份写死的口径，两端各说各话。

因此本期一次把两侧做齐，并把**角色、资金、租户、VA、通道、权限**六件事在**同一份文档里说死**。

两个前端工程**彼此独立**（不共享代码、可独立发版）。A 端自身也是合并产物：一期把原先分开的「业务管理后台」与「开发者门户」合并为**一个租户业务台**，租户不必在两个系统之间切换。

### 1.2 三端与使用人

```
白标门户（对外品牌站 · 本期不成文）
   │  租户的终端用户开户 / 用卡；开发者读 API 文档
   ▼
租户业务台（A 端 · 租户自用）
   │  管终端用户与 VA、看流水与账单、发密钥
   ▼
平台管理端（B 端 · 平台自用）
      审租户准入、发能力、定费率、做结算、管隔离与审计
```

### 1.3 一期目标（G1–G6）

| # | 目标 | 主要落在 |
|---|---|---|
| G1 | **准入线上化**：从邀请 / 申请到 `ACTIVE` 全流程线上留痕，审核 SLA 可度量 | B 端 |
| G2 | **租户自助化**：开户、充值与对账、密钥与 Webhook 全自助，终审不求助平台 | A 端 |
| G3 | **资金口径统一**：外扣模式 + 逐笔可核对 + 月结账单，两端同源 | A / B |
| G4 | **配置可控**：品牌 / 域名 / 邮件 / 费率由平台在授权区间内管，租户只审不进产线 | B 端 |
| G5 | **隔离可证明**：任一入口拿不到其他租户数据，越权有审计记录 | B 端 |
| G6 | **计费可对账**：每笔费用的归属、定价快照、结算与争议全链路可追溯 | B 端 |
| G7 | **租户自助开户运营**：谁在认证、钱有没有到、钱有没有出去，租户自己看得见 | A 端 |
| G8 | **租户财务自助对账**：这个月被计了多少手续费、账单在哪下载、线下汇款怎么核销 | A 端 |
| G9 | **租户研发自助接入自查**：密钥怎么管、回调为什么失败、怎么重投 | A 端 |
| G10 | **权限边界清晰**：不该看的菜单不渲染、不该点的按钮是禁用态、数据按租户与角色双重收窄 | A 端 |

### 1.4 一期不做什么

- 加密货币与卡片业务页（仅在工作台做**能力展示**，统计位显示「—」）。
- 租户自助 KYB（走平台代客开通 / 受邀申请）。
- 第三端白标门户的成文与品牌自助（自定义域名、品牌配置对租户开放）。
- 模式 A 渠道分销 / 租户持牌主商户两条路线；租户自带通道（Enterprise 选项）。
- **A 端不做结算单、争议与拒付处置**（这两件事在 B 端做，见 §4.9）。
- **不做分润划转**：储备金由平台侧统一管理（租户端不展示、不可充值），不用于扣费，也不作为分润通道。
- 存量历史租户数据迁移。

## 2. 名词表

| 名词 | 含义 | 端 |
|---|---|---|
| 白标租户（Tenant） | YASBe 的客户（白标方），对外用自己的品牌服务终端用户。演示租户：`Acme Payment Ltd.` · `TNT-000123` | A / B |
| 终端用户（End User） | 租户自己的客户，实名通过后可持有 VA | A / B |
| VA / 虚拟账户 | 银行级收款账号。口径：**一终端用户 × 一币种 = 一个 VA**，VA 开立即绑定通道 | A / B |
| 通道（Channel） | 实际签发账户与处理资金的持牌机构。**USD = Bridge**；**EUR / GBP = OpenPayd（Linked Client）** | A / B |
| 储备金（Reserve Account） | 平台侧为租户配置的流动性池，**仅用于出金流动性垫付与最低预存门槛，不用于扣减费用**；三币种独立，不折算计总；**2026-10-19 起租户端不展示、不可充值，由平台侧管理** | B 端可见 |
| 租户子账（Sub-ledger） | 平台侧对租户的账本载体：记录账单、收款与核销状态 | B 端 |
| 费用单据（FEE-…） | 每笔计费事件生成的费用记录，携带渠道 / 币种 / 费率 / 价格快照，计入当期账单，**不实时扣款** | A / B |
| 席位费（Seat Fee） | 按**管理员席位**计费：每个可登录的租户账号 / 月；终端用户不计席位 | A / B |
| 开户费 | 平台为终端用户开 VA 时向**租户**收取：**个人 VA $100 / 币种、企业 VA $1,000 / 币种**，不支持减免，随账单线下结算 | A / B |
| 挂账待认领 | 入金归因不唯一（附言缺失 / 多候选）时的入金挂账，需人工确认归属 | A / B |
| KYB | 租户准入的企业尽职调查（营业执照 / 法人身份证明 / 公司章程 / 地址证明 / 股东结构） | B 端 |
| KYC | 终端用户实名；材料在终端用户侧采集，A 端只展示归一状态与缺件 | A 端 |
| 身份验证器 | TOTP 动态口令应用（Google Authenticator 等），6 位码、30 秒刷新 | A / B |
| 能力授权（Capability Grant） | 逐租户开关：卡发行 / 虚拟账户 / 加密出入金 / 法币出入金 / API 接入 / 白标门户 | B 端 |
| 额度（Quota） | 单次开卡上限、持卡人上限、人均卡数、交易限额、日 / 月累计限额 | B 端 |
| 渠道费率表（Channel Rate Card） | 按「渠道 × 币种 × 方向 × 费用类型」逐格定义的唯一价格表；未配置的组合不可用 | B 端 |
| 账单（Invoice） | 按自然月聚合的费用账单；状态 `待确认 → 已出账 → 已收款 → 已核销`，A 端只读 | A / B |
| 价格快照 | 计费事件发生时冻结当时价格；**改价不追溯**已发生交易 | B 端 |
| 风控闸门 | 风险阈值与拦截规则；**仅平台可见可调，租户无入口、不可覆盖** | B 端 |
| 透视模式 | 平台侧跨租户查看的显式开关，进入即写审计 | B 端 |
| Go-Live 校验 | 置为 `ACTIVE` 的前置条件校验（KYB / 合约 / 网关 / 预存 / 域名邮件） | B 端（一期不启用，见 §4.2 注记） |
| 三级权限守卫 | A 端的实现纪律：路由级不渲染 + 按钮级禁用态 + 数据级 `tenant_id` 强制过滤 | A 端 |

### 3.4 三级权限守卫（A 端实现纪律）

1. **路由级**：角色无权的菜单**不渲染**（不是置灰后仍可点）；直接改 URL 进入 → `403` + 记审计，**不得静默返回空集**。
2. **按钮级**：只读角色看到**禁用态 + 悬浮说明**「你的角色为 {角色}，仅可查看」；危险动作（吊销 Live Key、认领挂账、充值确认、解绑身份验证器、移除成员）**一律二次确认**。
3. **数据级**：所有查询强制带 `tenant_id`；角色域再收窄（Finance 只见资金域与流水域，Developer 只见开发者域）。

> 原型实现：两个 HTML 属性驱动、不改 JS —— 区块/行级显隐用 `data-roles`，写操作按钮用 `data-role-allow`（无权 → `disabled` + `title` 提示）。


### 3.5 多租户隔离（B 端）

- **粒度**：行级隔离，`tenant_id` 为强制过滤维度；平台侧跨租户访问需显式「透视模式」开关，进入即写审计。
- **三层隔离**：数据隔离（租户 / 持卡人 / 交易 / 账单 / 日志按 `tenant_id` 分域）· 配置隔离（品牌 / 域名 / 邮件发件人 / 渠道费率表各自挂平台，租户不持有可改副本）· 能力隔离（能力开关 + 额度 + 通道与币种授权逐租户授权）。
- **越权防护**：改写 URL / 请求体中的租户标识 → `403` + 审计告警（不得静默返回空集）；租户角色访问平台专属页（能力开关、风控、费率基准）→ 入口不渲染 + 接口拒绝；同一浏览器多租户切换 → 会话级租户上下文，切换即清缓存与预签名链接。
- **可见性边界**：平台侧按角色域收窄；租户侧永久只见自己（A 端口径见 §3.4 三级守卫）。


### 3.6 不可下放清单（红线，写进合约而非配置项）

1. 风险闸门阈值与拦截规则不可被租户覆盖或调低。
2. 平台上游成本、通道采购价、底价不可对租户可见。
3. 平台资金归集 / 托管钱包地址不向租户展示（属平台账本内容）。
4. 其他租户的任何数据（含聚合值）不可见。
5. 平台保留文案 key（合规声明、费用说明、风控口径）不可覆写。


> 这五条在 A 端对应的表现是：**入口不渲染 + 接口拒绝**（不是置灰后仍可点）；在 B 端对应的表现是：只有平台特定角色可见，且变更一律留审计。

### 3.7 演示口径

页面左下角提供角色切换器，用来演示同一页面的三档差异；切换时提示"当前页面对该角色不可见"（演示越权守卫）。


- **透视模式（B 端）**：进入跨租户视角时顶部常驻「透视模式」标识，退出即恢复；进入与退出都写审计。
- **越权守卫（A 端）**：角色切换后若当前页面对该角色不可见，提示「当前页面对该角色不可见」，用于演示守卫生效。

## 4. 核心业务模型

### 4.1 资金与计费总口径（外扣 + 月度账单线下结算）

```
终端用户入金 ─┐
             ├─► 按「渠道 × 币种 × 方向」费率计费 ─► 生成费用单据（FEE-…，含价格快照）
终端用户出金 ─┘                                              │
付费动作（开 VA / 新增席位）──► 同口径计费 ───────────────────┤
                                                            ▼
                                                  计入当期账单（不实时扣款）
                                                            │
每月 1 日 ─► 生成上月账单（账期 × 渠道 × 币种）─► 财务线下对账 ─► 租户线下打款 ─► 平台核销
```

储备金 USD / EUR / GBP 三币种独立，由平台侧管理，**只用于出金流动性垫付与最低预存门槛**（租户端不展示、不可充值），费用不从储备金扣。

**关键纪律**

1. **外扣**：手续费由租户（商户）承担，**终端用户的本金不受影响**。UI 上「用户本金」与「手续费」必须分列，禁止合并成「合计」，否则财务会误判为内扣。
2. **费用不实时扣款**：席位费 / VA 开户费 / 出入金手续费一律计入当期账单，**不从任何余额扣减**；UI 不得出现「已从余额扣除」类表述。
3. **三币种不折算计总**：卡片、明细、账单都分币种列示，不出现跨币种合计。
4. **金额一律字符串表达**，前端不做浮点运算。
5. **逐笔可核对**：费用单据必须能回溯到交易号 / 计费动作 + 价格快照；错账靠反向冲正，不物理删记录。
6. **月结**：每月 1 日生成上月账单（账期 × 渠道 × 币种：费用合计、笔数、状态），可下载明细 CSV 与发票 PDF；本期未关账标「进行中」。
7. **线下打款**：账单状态 `待确认 → 已出账 → 已收款 → 已核销`；收款登记录 到账日期 / 金额 / 币种 / 银行流水号 / 付款凭证；支持部分收款与跨账单核销。
8. **两类约束分开**：储备金（平台侧）只约束**流水**（低于出金拦截线 → 出金被拒、入金放行）；**账单欠费不拦截任何交易**，只做提醒 + 限制增量能力（新开 VA / 新增席位 / 新开户）。

**与平台侧的关系（同一张账单）**

- A 端只读查看账单与费用明细；出账、收款登记、核销、争议裁定全部在 B 端由平台财务操作。
- A 端不展示储备金；储备金余额 = 平台子账，仅用于流动性判定与最低预存，不参与费用清算。
- 价格唯一真值 = **计费事件发生时的价格快照**（B 端 §4.8）；账单金额 = 当期快照金额之和。
- **N1 已关闭（2026-10-17）**：不再存在「周期结算至子账」与「实时扣减」两套口径。

### 4.2 租户生命周期与准入（B 端）

> **一期口径（MVP 收敛）**：平台侧「新增即开户」—— KYB 线下核验后只登记结论 + 归档合同，状态**直接 `已开户`**，不走下列准入中间态，因此一期**没有**「审核中」「待补件」「活跃」三种状态。下列 `DRAFT → … → ACTIVE` 状态机是完整准入模型，随租户自助申请版本启用。

```
DRAFT → SUBMITTED → UNDER_REVIEW
UNDER_REVIEW → INFO_REQUIRED → UNDER_REVIEW        （可多次循环，累计补件有上限）
UNDER_REVIEW → APPROVED → CONTRACT_PENDING → CONTRACT_SIGNED
CONTRACT_SIGNED → PENDING_FUNDING → ACTIVE
UNDER_REVIEW → REJECTED（不可修复：涉高风险行业 / 黑名单）
REJECTED → 冷却期后可重新提交（冷却时长待确认）
ACTIVE → SUSPENDED（欠费 / 合规事件）→ ACTIVE | TERMINATED
```

- 审核 SLA 从 `SUBMITTED` 起算，1–3 工作日；SLA 内未处理自动升级至平台超管。
- 驳回必须选原因码 + 自由文本：原因码区分**可修复**（文件不完整 / 信息不一致）与**不可修复**（涉高风险行业、股东或高管有不良记录），决定是否给重提入口。
- 补件回路 `INFO_REQUIRED`：逐条指定待补项、限 N 个自然日、超时自动关闭。


- **两条入口**：平台超管「代客开通」与受邀企业「自助申请」（带租户标识与有效期的邀请链接，过期失效）。
- **KYB 材料**：营业执照 / 法人身份证明 / 公司章程 / 地址证明 / 股东结构（如有）；格式与清晰度自动检查；人工 + 机器审核。
- **合约**：Fee Plan 定价模板 / 结算周期（T+1 或 T+7）/ 最低预存要求 / 开卡与交易限额；双侧签章状态留痕。
- **支付网关绑定**：提交网关资料 → 归属验证 → 生效 / 失败退回。
- **API Key 发放**：Sandbox / Prod 两套（`sk_test_` / `sk_live_` 前缀区分），scope 勾选，**密钥仅创建时展示明文**。
- **Go-Live 校验**（置为 `ACTIVE` 的必要条件）：`KYB 通过 ∧ 合约生效 ∧ 网关已绑定 ∧ 预存 ≥ 最低 ∧ 域名与邮件（若启用）已生效`。


### 4.3 开户费（两端统一口径）

| 类型 | 金额 | 收费方式 | 减免 |
|---|---|---|---|
| 个人 VA | **$100 / 币种** | 计入租户当期账单，随月度账单**线下打款**结算；终端用户不付费、钱包无需预存 | **不支持** |
| 企业 VA | **$1,000 / 币种** | 同上（计入租户当期账单，线下月结） | **不支持** |

> v1.2 口径变更：开户费由「终端用户钱包扣 USDT / USDC」改为「**平台向租户收取、随账单线下结算**」—— 所有费用统一走线下月结，不向终端用户收费。

### 4.4 通道映射与 VA

| 币种 | 通道 | 收款信息字段组 |
|---|---|---|
| USD | Bridge | 收款人 / 账号 `bank_account_number` / 路由号 `bank_routing_number` / 银行名与地址 |
| EUR | OpenPayd | 持有人 / `iban` / `bic` |
| GBP | OpenPayd | 持有人 / `sort_code`（6 位，无连字符）/ `account_number` |

- VA **开立即绑定通道**（因此多通道冗余只在出金侧成立）。
- 收款信息**只对该终端客户展示**；平台侧的归集账户与托管钱包属账本内容，**不在租户界面出现**。
- 路由号位数以上游开户返回为准，前端不硬编码。


**平台侧补充（B 端 VA 与开户作业）**

- VA 口径：**一终端用户 × 一币种 = 一个 VA**，VA 开立即绑定通道；VA 状态：开立中 / 已开通 / 已停用。
- 平台侧可查全部租户的 VA 与开户申请，按租户维度聚合（本月入金 / 出金 / 余额）。
- 开户费按 §4.3 的规则计收；开户失败要有失败原因与处置入口（重试 / 退回 / 联系租户）。
- 入金归因与挂账：VA 账号 → 附言 / reference → 上游流水号三路交叉，不唯一进挂账待认领（租户侧可只读 + 认领）。


### 4.5 入金归因与挂账

```
入金到账 ──► 三路交叉：VA 账号 → 附言 / reference → 上游流水号
                 ├─ 唯一匹配 ──► 记入对应终端用户，产出 attribution_key
                 └─ 不唯一 / 无附言 ──► 挂账待认领，人工确认归属
幂等键 =（tenant_id + 端点 + 幂等键）
```


### 4.6 状态机（对外归一，上游方言不进 UI）

**终端用户认证状态**：未开始 / 资料收集中 / 审核中 / 需补件 / 已通过 / 已拒绝 / 限制入金 / 已清退。
上游 `CustomerStatus` 与 `requirements`（`missing` / `issues`）只用于内部映射，页面展示"哪一项、什么问题"。

**VA 状态**：开立中 / 已开通 / 已停用（对应上游 `activated` / `deactivated`）。

**交易状态**：处理中 / 成功 / 失败 / 已退回；出金另带拦截原因（如 `可用余额不足`）。

**成员状态**：正常 / 待接受邀请 / 已停用。


**B 端补充状态**

- **租户状态**：`DRAFT` / `SUBMITTED` / `UNDER_REVIEW` / `INFO_REQUIRED` / `APPROVED` / `CONTRACT_PENDING` / `CONTRACT_SIGNED` / `PENDING_FUNDING` / `ACTIVE` / `SUSPENDED` / `TERMINATED` / `REJECTED`。
- **结算单状态**：`PENDING` → `CONFIRMED` → `PAID` → `CLOSED`。
- **争议状态**：挂起（冻结该笔）→ 裁定 → 调整 / 驳回。
- **开户申请状态**：开立中 / 已开通 / 已失败（失败可重试 / 退回 / 联系租户）。

### 4.7 能力、额度与通道授权（B 端）

- 能力矩阵逐项开关 + 生效时间：卡发行 / 虚拟账户 / 加密出入金 / 法币出入金 / API 接入 / 白标门户。
- 额度：单次开卡上限 · 持卡人上限 · 人均卡数 · 交易限额 · 日 / 月累计限额。
- 通道与币种授权：**USD = Bridge**；**EUR / GBP = OpenPayd（Linked Client）**；租户可用币种集合逐租户授权。
- 风控闸门只读展示给平台侧指定角色；阈值调整留审计，租户侧只看到结果口径。


### 4.8 费率与计费（B 端）

| 项 | 口径 |
|---|---|
| 配置维度 | **渠道 × 币种 × 方向 × 费用类型**，逐格独立配置；格与格之间不继承、不折算、不取平均 |
| 渠道 | Bridge（USD）· OpenPayd（EUR / GBP）· 链上（USDT / USDC，ETH / TRON） |
| 费用类型 | 席位费（每管理员席位 / 月）· 法币 VA 开户费（个人 / 企业，每币种）· 入金手续费 · 出金手续费 · 开卡费（一次性 / 张）· 交易 Spread（bps）· 提现费 · 退款手续费 |
| 未配置即不可用 | 某「渠道 × 币种 × 方向」组合没有费率 → 该组合的开户与交易直接拒绝，并提示「该组合未开通定价」；**不做默认价兜底** |
| 定价权 | 全平台一套渠道费率表，由平台超管维护，**租户不参与定价**；原「费率模板 + 授权区间 Markup / Discount + 底价保护」作废 |
| 价格快照 | 计费事件发生时冻结当格价格；**改价不追溯**已发生的计费事件 |
| 变更留痕 | 每次改价写审计（操作人 / 渠道 / 币种 / 前后值 / 生效时间）；生效时间只允许「立即」或「指定未来时间」 |
| 账单归属 | 平台 → 租户：服务费与通道成本；租户 → 终端用户：自有品牌定价（平台不代出账、不干涉） |

**法币 VA 开户费**（平台向租户收取，**不向终端用户收取**）：个人 VA **$100 / 币种**、企业 VA **$1,000 / 币种**、**不支持减免**；随当期账单线下结算，不再要求终端用户钱包预存 USDT / USDC 覆盖开户费。

### 4.9 结算、对账与争议（B 端）

- **分润**：平台留存 = 上游通道成本 + 平台加价（即渠道费率表中的价格）；租户向终端用户的定价由租户自主，平台不代出账。
- **账单**：按自然月 × 渠道 × 币种聚合，明细可下钻到费用单据与交易号；状态 `待确认 → 已出账 → 已收款 → 已核销`。
- **线下收款登记**：财务录入 到账日期 / 金额 / 币种 / 银行流水号 / 付款凭证；支持部分收款与一笔收款跨多张账单核销；差额走调整单留痕，不手改账单金额。
- **争议**：租户对某笔费用发起争议 → 冻结该费用单据 → 财务裁定 → 调整或驳回，全链路留痕。
- **欠费与催收**：已出账未收款 → 站内 + 邮件提醒 → 逾期限制增量能力（新开 VA / 新增席位 / 新开户）；**不拦截既有终端用户的出入金，不自动终止租户**。

> 与租户侧同一张账单、同一状态机：A 端只读、B 端操作；**N1 已关闭**，两端不再有第二套结算口径。

- **开 VA 弹窗（四步，照客户端 Bridge 开户原型搬）**：

### A.6 开发者中心

- **API Key 管理**：列表掩码展示（前 4 + `•` + 后 4）、环境列（Sandbox / Live）、scope、来源 IP、最后使用时间、创建人、状态；生成（名称 + 环境 + scope，**明文只显示一次**、须勾选"已妥善保存"才能关闭）· 轮换（**双密钥并存**，显示旧钥最后使用时间与近 24h 调用量）· 吊销（二次确认 + 输入密钥名末 4 位；吊销后保留在列表里留痕）。**Live 环境生成/吊销强制 2FA**。
- **Webhook 端点**：端点 URL（只接受 HTTPS，禁止内网/回环地址）、订阅事件（默认不订阅，需显式勾选）、端点密钥（掩码 + 重置）、验证投递（未通过不允许启用）、暂停/恢复（熔断后需人工确认 + 重新验证）。
- **投递日志**：事件 ID / 类型 / 投递时间 / HTTP 状态码 / 耗时 / 尝试次数 / 下次重试 / 响应片段 / 操作（重投、复制原始 body 与 headers）；三态不可混：重试中（自动，带倒计时）→ 待重投（自动已耗尽，需人工）→ 投递成功。页脚常驻提醒（**面向客户文案，禁用内部词**）：「Webhook 是通知，不是最终依据；余额与流水以查询接口 `GET /v1/reconciliation` 为准」。同时列出验签（原始请求体参与 HMAC-SHA256）· 重试（退避至 8 次后转「待重投」）· 重复投递（按 `X-YASBe-Event-Id` 去重）。
- 签名：`X-YASBe-Signature: t=<时间戳>,v1=<HMAC-SHA256(t + "." + 原始请求体, 端点密钥)>`，另有 `X-YASBe-Event-Id`；指数退避最多 8 次 / 最长 24 小时，单次超时 10 秒；按 `event.id` 幂等去重。

### A.7 账户管理（设置组，仅管理员）

**目标**：管本租户的**成员与角色**（人员账号），与「账号设置」（本人凭据）互不重叠。

- 统计条：成员总数（含待接受邀请）· 管理员 · 财务 · 研发
- 筛选：搜索（姓名 / 邮箱）+ 角色 + 状态
- 平铺表格：成员（姓名 + 邮箱）/ 角色 / 状态 / 最近登录 / 操作

- 本人账号行不可操作（改角色/停用均禁用）
- 侧栏项**仅对管理员渲染**（路由级守卫）

- **席位计费提示（v1.2）**：页面常驻一行「当前 {X} 个管理员席位；席位费按**管理员账号 / 月**计，随月度账单线下结算，新增席位自生效当月起计费」；**终端用户不计席位**。

### A.8 账号设置（设置组，三角色可见）

**目标**：管理**本人**的登录凭据与安全验证方式。**每个功能一张卡，卡片只做只读汇总，改值一律走弹窗**（页内不放表单）。

| 卡片 | 展示 | 弹窗动作 |

| 登录密码 | 状态已设置 / 上次修改 / 建议 90 天更换 | 修改密码（当前密码 + 新密码 + 确认；保存后其它设备会话失效） |

### B.1 租户列表（M2）

- 统计条：租户总数 / 已开户 / 暂停 / 本月用量 / 本月应收（**不含**「审核中」「待补件」「活跃」等准入中间态，一期不启用）。
- 筛选：状态（已开户 / 暂停）、地区；平铺表格，按新增时间倒序。**无「计费套餐」维度** —— 全平台一套渠道费率表（渠道 × 币种逐格独立），费用按账期线下结算（见 B.7）。
- 行操作：查看费率（只读，租户不参与定价）、充值余额、查看密钥、暂停 / 启用、进入详情。
- **状态只有两态**：`已开户` ⇄ `暂停`；**终止不在此页发起**，统一在租户详情内二次确认（填原因 + 影响面提示，见 B.3）。
- 新增入口：「新增租户」→ 新增即开户弹窗（见 B.2）。
- 审核员可见但只读（仅审核队列视角）。

### B.2 新增租户（新增即开户，M1）

平台超管在租户列表点「新增租户」，**一个弹窗填完即开户** —— 不走向导、不设审核中间态：

- 登记项：企业基础信息（注册邮箱 / 公司名 / 法人 / 注册地址 / 联系人与电话）+ **KYB 线下登记**（材料已线下核验，此处只记结论）+ 合同附件归档。
- 同屏设定：开户费（按 VA 类型，见 §4.3，**只读展示**）、适用渠道费率（只读，见 B.7）、结算方式（**账期线下结算，每月 1 日出账**）。
- 提交后：状态**直接置 `已开户`**；余额 0，能力默认关闭；开立 VA 只受能力开关约束，不再设充值门槛（储备金由平台侧管理）。
- 留痕：新增动作写审计（操作人 / 前后值 / 时间）；合同与 KYB 结论随租户详情（B.3）可查。
- **一期不启用**：`DRAFT → SUBMITTED → UNDER_REVIEW → … → ACTIVE` 七步向导（KYB 逐项打标 / 电子合约双侧签章 / 网关绑定 / API Key 发放 / Go-Live 校验）作为完整准入模型保留在 §4.2，随租户自助申请版本启用；一期 KYB 全部走线下，**不存在「审核中」「待补件」状态**。

### B.3 租户详情总览

主体信息 · KYB 结论与材料 · 合约状态 · 网关绑定 · 子账与余额 · 能力开关摘要 · 域名与邮件健康态 · **席位与账单摘要**（当前管理员席位数 / 本月账单金额与状态） · 关联账号（租户管理员与子账号的启停 / 重置 / 登录审计）· 变更入口（跳各子页）。

### B.4 法币 VA（平台侧）

- 统计条 + 筛选（关键词 / 状态 / 币种 / 开立时间）+ 平铺表格：**租户 · VA 号 · 终端客户 · 类型 · 币种 · 状态 · 开户费 · 开立时间 · 本月入金 · 本月出金 · 余额 · 操作**；分页（共 N 条 · 每页 10 条）。
- 行操作：详情、入金指引。
- 状态：`已开通` / `开立中` / `已停用`（三态，与终端客户侧看到的账户状态一致）。
- **开立法币 VA 弹窗**：开户费规则（见 §4.3）→ 客户类型（个人 / 企业）→ 币种（USD / EUR / GBP）→ 终端客户引用号 → 终端客户姓名 / 主体名 → 应缴开户费（随类型变化，只读）→ 终端用户钱包余额（USDT / USDC，可演示充足 / 不足）→ 开立原因 / 备注 → 生效时间（立即 / 指定时间）→ 提交开立。

### B.5 开户记录

### B.6 交易流水查询

### B.8 能力与额度

### B.9 结算与对账

- 平台角色的权限配置（能力 × 角色）与不可下放红线提示。

### B.11 品牌配置 · 域名与邮件（大纲内，未出原型，后续）

品牌资产（logo Light/Dark、favicon、登录页背景）· 主题 token（默认 `#FFCA00 → #FE5707`，仅允许区间内派生 + 对比度检查）· 文案字典（平台保留 key 不可覆写）· 邮件模板（邀请 / 验证 / 对账单 / 异常四类）· 品牌预览与发布（可一键回滚）· 自定义域名（唯一性与保留域校验 → CNAME + TXT 校验 → SSL 自动签发与续期）· 邮件发件域（SPF / DKIM / DMARC）与自带 SMTP（测试发信通过才可启用）· 失败一律**显式回退**到平台默认并告知。

## 8. 风控与合规

### 8.1 A 端 · 终端用户与租户自用侧

1. **实名**：终端用户 KYC 走合作机构托管核验（EEA 人脸、美国居民政府证件照）；租户侧只展示归一后的状态与缺件。
2. **二次验证（2FA）**：TOTP 6 位 / 30 秒；绑定、解绑、修改邮箱、修改密码、Live 密钥生成与吊销、收款信息变更确认等敏感操作均需二次验证。
3. **密钥安全**：明文只在创建时展示一次；服务端只存哈希；密钥不进 URL、不进日志、不进审计详情（审计只记名称与 ID）。
4. **入金/出金筛查**：钱包地址走地址筛查（风险等级 0–5），高风险转人工；入金被拒结由后台自动退款（平台侧口径）。
5. **操作留痕**：成员停用/移除、角色调整、密钥轮换与吊销、充值、认领挂账等均留痕；审计日志页一期后补。
6. **PII**：终端用户 PII 只在租户范围内可见；平台专属项（归集地址、成本、底价、风控阈值）不渲染、接口拒绝。


### 8.2 B 端 · 平台与多租户侧

1. **风控闸门不可下放**：阈值与拦截规则只允许平台在划定区间内调整并留审计；租户侧无入口、不可覆盖（写进合约）。
2. **风险扫描**：加密出入金按地址筛查（`risk_level ≥ 3` 拦截、0–2 放行），白标侧不可覆盖。
3. **KYB 材料**：加密存储、访问留痕，保留期按地区合规要求。
4. **密钥安全**：明文仅创建时展示；只存哈希；不进 URL / 日志 / 审计详情（审计只记名称与 ID）。
5. **SLA 与升级**：审核超 SLA 自动升级；驳回必须选原因码，区分可修复 / 不可修复。
6. **资金合规**：payment 模式下资金先入平台主账户；平台归集与托管钱包地址不向租户展示。

## 11. 非功能需求

### 11.1 A 端

- **幂等**：所有写操作与回调按 `event.id` / 幂等键去重，重投不产生重复记账。
- **时区**：界面上时间统一按租户时区展示，账单账期按自然月（GMT+8 由租户设置决定）。
- **性能**：列表首屏 ≤ 2s（含统计条）；导出异步生成。
- **可用性**：账单与交易流水为关键路径，接口失败要有明确文案与重试指引。
- **可访问性/多语言**：按钮与表单有 title/占位说明；一期仅中文，术语表预留中英对照键。


### 11.2 B 端

- **隔离性**：任何租户域查询不可出现跨租户数据（可测断言）。
- **可用性**：配置类变更不重启服务、不中断在途交易。
- **性能**：租户列表与结算单分页响应阈值（具体值待定）。
- **审计**：必录字段齐全、可导出、保留期按合规要求。
- **一致性**：平台侧与租户侧对同一笔费用的口径必须一致（价格快照为唯一真值）。


### 11.3 跨端一致性（新增）

- **同源**：A 端看到的账单与费用明细、B 端账单与收款核销记录必须来自同一账本与同一价格快照，禁止各算各的；储备金在平台侧单独只做流动性判定。
- **幂等**：两端写操作与回调统一按幂等键去重，重投不重复记账。
- **时区**：租户侧展示按租户时区；平台侧结算账期按自然月。
- **审计**：平台侧所有变更（含代租户改配置、透视查看）必留痕且可导出；A 端敏感操作留痕。

## 13. 验收标准（节选）

### 13.1 A 端（租户业务台）

1. **权限**：以 Finance 登录，侧栏不出现 API Key / Webhook / 投递日志 / 账户管理；在虚拟账户页「＋ 新增虚拟账户」为禁用态且鼠标悬浮显示「你的角色为财务，仅可查看」；直接输入 URL 进入开发者页得到 403（真实环境）或越权提示（原型）。
2. **资金**：首页不出现储备金告警条，GBP 状态体现在「本期账单卡」与左侧租户卡；账单页 GBP 本期金额 96.40、待收款 3 张；页面**不出现任何扣费记录**，费用只出现在账单与费用明细里；
3. **开户**：管理员点「＋ 新增虚拟账户」→ 四步弹窗可前进后退；未签《Bridge 服务条款》时勾选框为禁用且不可手动勾选；提交后 VA 状态为「开立中」。
4. **账号设置**：页内不含任何输入框（改值全部在弹窗）；修改密码保存后提示其它设备需重新登录；解绑身份验证器为 danger 按钮并写清影响。
5. **账户管理**：邀请成员 24 小时内有效；本人账号行不可改角色、不可停用；移除后成员不再出现在列表。
6. **交互**：所有弹窗支持 `×`、`Esc`、点遮罩三种关闭方式；顶部用户区可点进账号设置。
7. **文案**：客户可见文案闸门 0 ERROR / 0 WARN；所有页面各含 1 条 PM 备注。


### 13.2 B 端（平台管理端）

1. **新增即开户**：新增租户必须填齐企业基础信息 + KYB 线下结论 + 合同归档，提交后状态直接 `已开户`（无审核中间态、无 Go-Live 校验）；租户未充值前开立 VA 被拒绝并提示先充值。
2. **补件回路**：驳回项逐条可指定，租户侧看到待补清单；超期自动关闭；不可修复原因不给重提入口。
3. **隔离**：改写请求中的 `tenant_id` → `403` + 审计告警（不是空列表）；租户角色访问平台专属页 → 入口不渲染。
4. **计费**：某「渠道 × 币种 × 方向」未配置费率时，开户 / 交易被拒绝并提示「该组合未开通定价」（不回落默认价）；改价后已发生的费用单据金额不变（价格快照）；账单状态按 `待确认 → 已出账 → 已收款 → 已核销` 流转，收款登记缺凭证不可核销。
5. **结算**：结算单可下钻到交易号；争议发起后该笔被冻结、裁定后写审计；欠费只降级不终止。
6. **VA 作业**：按月维度能看到某租户的 VA 数、本月入金 / 出金笔数与余额；开户费按个人 / 企业类型正确取 $100 / $1,000；失败开户有处置入口。
7. **风控**：风控阈值租户侧无入口；阈值变更留审计（含前后值）。


### 13.3 跨端（新增）

1. **同源**：同一租户在 A 端账单页看到的手续费与账单金额，与 B 端该租户的费用明细 / 结算单金额一致（价格快照为唯一真值）；N1 未定稿前以 A 端口径为准。
2. **边界**：租户角色访问平台专属页 → 入口不渲染 + 接口拒绝；平台超管进入租户域必须显式开启透视模式，且进入 / 退出都写审计。
3. **开户费一致**：两端对同一笔 VA 开户展示同一金额（个人 $100、企业 $1,000 × 币种），且不支持减免的规则在两端都不给「减免」入口。
4. **隔离**：改写请求中的 `tenant_id` → `403` + 审计告警（不是空列表）。
