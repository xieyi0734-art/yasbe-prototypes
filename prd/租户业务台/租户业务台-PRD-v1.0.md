## 1. 背景与目标

### 1.1 业务背景

YASBe 对外提供白标（White-Label）BaaS：平台把「法币 VA 开户 + 出入金」的能力转授给租户（我们的客户，例如一家支付服务商），租户再服务自己的终端用户。系统有**三个完全独立的前端工程**，不共享代码、可独立发版：

| 工程 | 使用者 | 职责 |
|---|---|---|
| 白标门户（对外文档站） | 租户的研发 | API 文档、接入指引、事件字典 |
| **租户业务台（本稿）** | **租户自己的人员**（管理员 / 财务 / 研发） | 看人（终端用户）、看钱（储备金与流水）、看接口（API Key 与 Webhook） |
| 平台运营总台（管理端） | YASBe 自己的运营 | 租户准入与 KYB、开户作业、费率与结算、风控 |

一期把原先分开的「业务管理后台」与「开发者门户」**合并为租户业务台**：租户不必在两个系统之间切换。

### 1.2 目标（一期）

1. 租户能自助完成终端用户的开户（VA 开立）与日常运营：谁在认证、钱有没有到、钱有没有出去。
2. 租户财务能**自己做对账**：储备金余额为什么变了、这个月被扣了多少手续费、账单在哪下载。
3. 租户研发能**自己接入与自查**：密钥怎么管、回调为什么失败、怎么重投。
4. 权限边界清晰：**不该看的菜单不渲染、不该点的按钮是禁用态、数据按租户与角色双重收窄。**

### 1.3 不做什么（一期）

- 不做加密货币与卡片的业务功能（仅在工作台首页展示"未开通"状态）。
- 不做租户侧的自助 KYB（租户准入在平台侧完成）。
- 不做结算单、争议与拒付处置（一期后补）。
- 不做分润划转（储备金只用于扣费）。

## 2. 名词表

| 名词 | 含义 |
|---|---|
| 租户（Tenant） | YASBe 的客户（白标方），本系统就是它的后台。示例演示租户：`Acme Payment Ltd.` · `TNT-000123` |
| 终端用户（End User） | 租户自己的客户，实名通过后可持有 VA |
| VA / 虚拟账户 | 银行级收款账号。口径：**一终端用户 × 一币种 = 一个 VA**，VA 开立即绑定通道 |
| 通道（Channel）/ 上游 | 实际签发账户与处理资金的持牌机构。**USD = Bridge**；**EUR / GBP = OpenPayd（Linked Client）** |
| 储备金（Reserve Account） | 租户预存的付费子账：只出不进（充值进、手续费出），**不折算合计（三币种独立）** |
| 手续费扣减 | 每笔终端用户出入金产生的手续费，从租户储备金划出，记一条费用单据 |
| 开户费 | 为终端用户开 VA 时一次性收取的费：**个人 VA $100 / 币种、企业 VA $1,000 / 币种**，不支持减免 |
| 挂账待认领 | 入金归因不唯一（附言缺失/多个候选）时的入金挂账，需人工确认归属 |
| KYB / KYC | 租户准入 = KYB（平台侧）；终端用户实名 = KYC（租户侧展示状态，材料在终端用户处采集） |
| 身份验证器 | TOTP 动态口令应用（Google Authenticator 等），6 位码、30 秒刷新 |

### 3.3 三级权限守卫（实现纪律）

1. **路由级**：角色无权的菜单**不渲染**（不是置灰后仍可点）；直接改 URL 进入 → `403` + 记审计，**不得静默返回空集**。
2. **按钮级**：只读角色看到**禁用态 + 悬浮说明**「你的角色为 {角色}，仅可查看」；危险动作（吊销 Live Key、认领挂账、充值确认、解绑身份验证器、移除成员）**一律二次确认**。
3. **数据级**：所有查询强制带 `tenant_id`；角色域再收窄（Finance 只见资金域与流水域，Developer 只见开发者域）。

> 原型实现：两个 HTML 属性驱动、不改 JS —— 区块/行级显隐用 `data-roles`，写操作按钮用 `data-role-allow`（无权 → `disabled` + `title` 提示）。

### 3.4 演示口径（原型内的角色切换器）

页面左下角提供角色切换器，用来演示同一页面的三档差异；切换时提示"当前页面对该角色不可见"（演示越权守卫）。

## 4. 核心业务模型

### 4.1 资金与计费（对外扣模式）

```
租户充值 ──► 储备金 USD / EUR / GBP（三币种独立，不折算计总）
                 │
终端用户入金 ──► 扣手续费 ──► 记一条费用单据（FEE-…）
终端用户出金 ──► 扣手续费 ──► 记一条费用单据（FEE-…）
                 │
        余额下探 ──► 三档告警：充足（≥ 预警线） / 预警（< 预警线，仍放行 + 告警） / 不足（≤ 出金拦截线，拦截出金）
```

**关键纪律**

1. **外扣**：手续费由租户（商户）承担，**终端用户的本金不受影响**。UI 上「用户本金」与「手续费」必须分列，禁止合并成「合计」，否则财务会误判为内扣。
2. **三币种不折算计总**：卡片、明细、账单都分币种列示，不出现跨币种合计。
3. **拦截发生在记账之前**：储备金不足 → 出金直接拒单（不产生扣费记录）；入金放行（终端用户的钱不该因商户欠费被拒），手续费转欠费挂账。
4. **金额一律字符串表达**，前端不做浮点运算。
5. **出金拦截线** = 单笔最高手续费预估值；余额 ≤ 该值即判「不足」。页面必须把「预警线」与「出金拦截线」两个阈值都摆出来，让"不足"可自证。
6. **逐笔可核对**：扣减明细必须带「扣减后余额」列；错账靠反向冲正，不物理删记录。
7. **月结**：每月 1 日生成上月账单（按账期 × 币种：手续费合计、扣减笔数、状态），可下载账单明细 CSV 与发票 PDF；本期未关账时标明"进行中"。

### 4.2 开户费

| 类型 | 金额 | 收费方式 |
|---|---|---|
| 个人 VA | **$100 / 币种** | 需终端用户钱包内有足额 USDT / USDC（支持以太链与波场链）覆盖 |
| 企业 VA | **$1,000 / 币种** | 暂不需要提前交费，记账后收取 |
| 减免 | **不支持**，按标准价执行 | — |

### 4.3 通道映射与 VA

| 币种 | 通道 | 收款信息字段组 |
|---|---|---|
| USD | Bridge | 收款人 / 账号 `bank_account_number` / 路由号 `bank_routing_number` / 银行名与地址 |
| EUR | OpenPayd | 持有人 / `iban` / `bic` |
| GBP | OpenPayd | 持有人 / `sort_code`（6 位，无连字符）/ `account_number` |

- VA **开立即绑定通道**（因此多通道冗余只在出金侧成立）。
- 收款信息**只对该终端客户展示**；平台侧的归集账户与托管钱包属账本内容，**不在租户界面出现**。
- 路由号位数以上游开户返回为准，前端不硬编码。

### 4.4 入金归因

```
入金到账 ──► 三路交叉：VA 账号 → 附言 / reference → 上游流水号
                 ├─ 唯一匹配 ──► 记入对应终端用户，产出 attribution_key
                 └─ 不唯一 / 无附言 ──► 挂账待认领，人工确认归属
幂等键 =（tenant_id + 端点 + 幂等键）
```

### 4.5 状态机（对外归一，上游方言不进 UI）

**终端用户认证状态**：未开始 / 资料收集中 / 审核中 / 需补件 / 已通过 / 已拒绝 / 限制入金 / 已清退。
上游 `CustomerStatus` 与 `requirements`（`missing` / `issues`）只用于内部映射，页面展示"哪一项、什么问题"。

**VA 状态**：开立中 / 已开通 / 已停用（对应上游 `activated` / `deactivated`）。

**交易状态**：处理中 / 成功 / 失败 / 已退回；出金另带拦截原因（如 `储备金不足`）。

**成员状态**：正常 / 待接受邀请 / 已停用。

## 5. 功能需求

导航结构（一期实际交付）：

```
概览   ▦ 工作台首页
业务   ◍ 虚拟账户（原「终端用户」，2026-10-15 改名） ▸ 下钻：终端用户详情
       ⇄ 交易流水
```

### 5.1 工作台首页

**目标**：一眼回答四件事 —— 服务开了哪些、钱够不够、有没有卡住的事、接口通不通。

| 区块 | 内容 | 角色可见性 |
|---|---|---|
| 门面 | 价值主张文案（加密货币 & 法币出入金解决方案 / MPC 钱包等） | 三角色 |
| 平台服务 | 三张服务卡：法币账户（已开通，展示支持币种、终端用户数、本月入/出金笔数）· 加密货币（未开通）· 卡片（未开通） | 三角色（待确认 R3） |
| 资金告警条 | GBP 储备金不足 → 出金被拦截，附「去储备金页」直达 | Admin / Finance |
| 储备金卡 | 三币种余额与告警档位 | Admin / Finance |
| 待办卡 | 需补件用户 / 挂账待认领 / 储备金预警（与通知同源、可深链） | Admin / Finance |
| 接入健康度卡 | 有效密钥数 / 近 24h 投递成功率 / 待重投事件 | Admin / Developer |
| 最近通知 | 最近 5 条：类型（风险 / 资金 / 客户 / 开发 / 账单）+ 标题 + 一句说明 + 时间 + 未读点，**每条深链到对应页面**；右上「全部已读」「查看全部」 | 通知按类型过滤（资金类仅 Admin/Finance，开发类仅 Admin/Developer），条数按角色实时计算 |

**纪律**：未开通的服务，统计位用「—」占位（不写 0，避免读成"已开通但没量"）；不出现开通入口与报价。

### 5.2 虚拟账户（菜单名；原「终端用户」）

**目标**：租户在这里管理"谁持有哪个币种的收款账号"，并代客发起开户。

- 页面标题与面包屑：`租户业务台 / 业务 / 虚拟账户`。
- 列表：统计条（终端用户数 / 认证已通过 / 需补件）+ 筛选（搜索姓名邮箱用户引用号、认证状态）+ 平铺表格（终端用户 / 用户引用号 / 居住国 / 认证状态 / 虚拟账户 / 操作）；需补件整行高亮；点进 **终端用户详情**。
- 页头动作：**「＋ 新增虚拟账户」**（仅管理员可用，其余角色禁用态 + 悬浮说明）。
- **开 VA 弹窗（四步，照客户端 Bridge 开户原型搬）**：

| 步 | 内容 |
|---|---|
| 1 选择账户类型 | 关联终端用户（下拉）+ 账户类型三选一：**USD（Bridge）** / EUR（OpenPayd）/ GBP（OpenPayd），切换更新签发机构说明；展示开户费规则（个人 $100 / 币种、企业 $1,000 / 币种，不支持减免） |
| 2 签署服务条款 | 《Bridge 服务条款》状态「待签署」→「前往签署」（合作机构托管页）；授权勾选框为**只读回填**（签署完成后自动勾选，不可手动改） |
| 3 填写账户信息 | 基本信息（名 / 中间名 / 姓 / 名与姓拼音 / 出生日期 / 国籍 / 邮箱 / 手机号）· 身份证明（证件类型 / 号码 / 签发国 / 有效期 / 正反面照片 / 人脸自拍，含 EEA 与美国居民的托管核验入口）· 居住地址（国家 / 详细地址 / 地址拼音 / 城市 / 省州 / 邮编 / 地址证明）· 资金用途与就业信息 |
| 4 确认提交 | 实名核验与开通时效说明 + 勾选《YASBe 平台服务条款》与《隐私政策》→「提交开户」 |

- 提交后 VA 进入「开立中」，开户完成转「已开通」，收款信息对该终端客户可见。

**待确认**：租户代客开户时，第 3 步是否改为"引用该终端用户已通过的实名资料 + 只读回显缺件"（客户端那份是用户自己填）——见 R8；列表是否改成 VA 维度（一行一个 VA：VA 号 / 终端客户 / 类型 / 币种 / 状态 / 开户费 / 开立时间 / 本月进出 / 余额）——见 R7。

### 5.3 终端用户详情（下钻页，不入菜单）

认证状态、缺件清单（缺什么、什么问题）、KYC 材料、名下 VA 与收款信息（按币种给不同字段组）、开立新账户入口、发送补件提醒。**收款信息只对本人展示**。

### 5.4 交易流水

入金 / 出金筛选 + 平铺表格 + **右侧抽屉详情**：把「用户本金」与「手续费」拆成两行两量纲，抽屉顶部常驻一句「本笔手续费由商户承担，终端用户不受影响」；出金被拦截时抽屉显示红色告警条（未产生扣费）。支持导出 CSV、复制交易号。

### 5.5 储备金与账单

| 区块 | 内容 |
|---|---|
| 三币种卡 | 可用余额 + **预警线** + **出金拦截线**；不足时给红色说明（已低于单笔最高手续费预估，新出金会被拒绝；入金不受影响） |
| 手续费扣减明细 | 扣费时间 / 费用单据号 / 币种 / 业务类型 / 用户本金 / 手续费 / **扣减后余额** / 状态；表尾给分币种合计；只读，错账走反向冲正 |
| 月度账单 | 账期 × 币种：手续费合计 / 扣减笔数 / 状态（已结算）+ 「账单明细 CSV」「发票 PDF」；本期未关账标注"进行中，次月 1 日生成"；卡片头另有「导出台账 CSV」 |
| 充值弹窗 | 充值币种 / 金额 / 收款信息（收款方、账号、参考号）+ 汇款附言说明 + 提交充值申请（多角色可见性按矩阵） |

**纪律**：本页的充值收款账户是给租户自己充值的、必须展示；平台资金归集地址不在租户界面出现，两者不要混在一处。

### 5.6 开发者中心

- **API Key 管理**：列表掩码展示（前 4 + `•` + 后 4）、环境列（Sandbox / Live）、scope、来源 IP、最后使用时间、创建人、状态；生成（名称 + 环境 + scope，**明文只显示一次**、须勾选"已妥善保存"才能关闭）· 轮换（**双密钥并存**，显示旧钥最后使用时间与近 24h 调用量）· 吊销（二次确认 + 输入密钥名末 4 位；吊销后保留在列表里留痕）。**Live 环境生成/吊销强制 2FA**。
- **Webhook 端点**：端点 URL（只接受 HTTPS，禁止内网/回环地址）、订阅事件（默认不订阅，需显式勾选）、端点密钥（掩码 + 重置）、验证投递（未通过不允许启用）、暂停/恢复（熔断后需人工确认 + 重新验证）。
- **投递日志**：事件 ID / 类型 / 投递时间 / HTTP 状态码 / 耗时 / 尝试次数 / 下次重试 / 响应片段 / 操作（重投、复制原始 body 与 headers）；三态不可混：重试中（自动，带倒计时）→ 待重投（自动已耗尽，需人工）→ 投递成功。页脚常驻提醒："Webhook 是通知不是真值源，请用对账接口兜底"。
- 签名：`X-YASBe-Signature: t=<时间戳>,v1=<HMAC-SHA256(t + "." + 原始请求体, 端点密钥)>`，另有 `X-YASBe-Event-Id`；指数退避最多 8 次 / 最长 24 小时，单次超时 10 秒；按 `event.id` 幂等去重。

### 5.7 账户管理（设置组，仅管理员）

**目标**：管本租户的**成员与角色**（人员账号），与「账号设置」（本人凭据）互不重叠。

- 统计条：成员总数（含待接受邀请）· 管理员 · 财务 · 研发
- 筛选：搜索（姓名 / 邮箱）+ 角色 + 状态
- 平铺表格：成员（姓名 + 邮箱）/ 角色 / 状态 / 最近登录 / 操作
- 操作：邀请成员（邮箱 + 角色 + 权限说明；邀请邮件 24 小时内有效，首次登录需设密码并绑定身份验证器）· 调整角色 · 停用（可随时启用，记录保留）· 移除（失去访问权限，历史记录保留在审计日志）· 撤销/重发邀请
- 本人账号行不可操作（改角色/停用均禁用）
- 侧栏项**仅对管理员渲染**（路由级守卫）

### 5.8 账号设置（设置组，三角色可见）

**目标**：管理**本人**的登录凭据与安全验证方式。**每个功能一张卡，卡片只做只读汇总，改值一律走弹窗**（页内不放表单）。

| 卡片 | 展示 | 弹窗动作 |
|---|---|---|
| 账号信息 | 姓名 / 所属租户 / 上次登录 | —（不可改，由平台侧维护） |
| 登录密码 | 状态已设置 / 上次修改 / 建议 90 天更换 | 修改密码（当前密码 + 新密码 + 确认；保存后其它设备会话失效） |
| 登录邮箱 | 已验证 / 当前邮箱（脱敏）/ 用途 | 修改邮箱（新邮箱 + 验证码 + 动态码确认；原邮箱收到变更通知） |
| 身份验证器 | 已绑定 Google Authenticator（TOTP）· 绑定时间 · 适用场景 | 重新绑定（扫码 + 手动密钥 + 6 位动态码）/ 解绑（二次验证确认身份；解绑后敏感操作退回邮箱验证码，两端口径待统一） |
| 登录设备 | 3 台（本机标识）+ 最近活跃时间 | 单台退出 / 退出所有其它设备（二次确认） |

## 7. 风控与合规

1. **实名**：终端用户 KYC 走合作机构托管核验（EEA 人脸、美国居民政府证件照）；租户侧只展示归一后的状态与缺件。
2. **二次验证（2FA）**：TOTP 6 位 / 30 秒；绑定、解绑、修改邮箱、修改密码、Live 密钥生成与吊销、储备金充值确认等敏感操作均需二次验证。
3. **密钥安全**：明文只在创建时展示一次；服务端只存哈希；密钥不进 URL、不进日志、不进审计详情（审计只记名称与 ID）。
4. **入金/出金筛查**：钱包地址走地址筛查（风险等级 0–5），高风险转人工；入金被拒结由后台自动退款（平台侧口径）。
5. **操作留痕**：成员停用/移除、角色调整、密钥轮换与吊销、充值、认领挂账等均留痕；审计日志页一期后补。
6. **PII**：终端用户 PII 只在租户范围内可见；平台专属项（归集地址、成本、底价、风控阈值）不渲染、接口拒绝。

## 9. 成功指标（一期）

- **激活**：新租户 7 日内完成首个 VA 开户的比例
- **自助率**：终审不求助平台（无工单）的终端用户开户占比
- **对账效率**：财务在储备金页完成一次对账所需操作步数（目标 ≤ 3 步：看余额 → 看明细 → 下载账单）
- **接入健康**：Webhook 近 24h 成功率；待重投事件数的中位数
- **安全**：2FA 绑定率（管理员 100%）；密钥泄露事件 0

## 10. 非功能需求

- **幂等**：所有写操作与回调按 `event.id` / 幂等键去重，重投不产生重复记账。
- **时区**：界面上时间统一按租户时区展示，账单账期按自然月（GMT+8 由租户设置决定）。
- **性能**：列表首屏 ≤ 2s（含统计条）；导出异步生成。
- **可用性**：储备金与交易流水为关键路径，接口失败要有明确文案与重试指引。
- **可访问性/多语言**：按钮与表单有 title/占位说明；一期仅中文，术语表预留中英对照键。

## 12. 验收标准（节选）

1. **权限**：以 Finance 登录，侧栏不出现 API Key / Webhook / 投递日志 / 账户管理；在虚拟账户页「＋ 新增虚拟账户」为禁用态且鼠标悬浮显示「你的角色为财务，仅可查看」；直接输入 URL 进入开发者页得到 403（真实环境）或越权提示（原型）。
2. **资金**：GBP 余额为 0 时首页出现拦截告警条；储备金页 GBP 卡显示"不足"、出金拦截线 40.00、明细中对应出金行的"扣减后余额"为 0.00；月度账单 2026-09 三个币种状态为已结算且可下载。
3. **开户**：管理员点「＋ 新增虚拟账户」→ 四步弹窗可前进后退；未签《Bridge 服务条款》时勾选框为禁用且不可手动勾选；提交后 VA 状态为「开立中」。
4. **账号设置**：页内不含任何输入框（改值全部在弹窗）；修改密码保存后提示其它设备需重新登录；解绑身份验证器为 danger 按钮并写清影响。
5. **账户管理**：邀请成员 24 小时内有效；本人账号行不可改角色、不可停用；移除后成员不再出现在列表。
6. **交互**：所有弹窗支持 `×`、`Esc`、点遮罩三种关闭方式；顶部用户区可点进账号设置。
7. **文案**：客户可见文案闸门 0 ERROR / 0 WARN；所有页面各含 1 条 PM 备注。
