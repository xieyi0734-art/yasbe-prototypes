## 1. 产品概述

### 1.1 背景

客户端 Rewards 页展示客户两类资产：**YASBee Cash**（购买 / 空投赠送获得的资产）与 **YASBee Points**（客户自操作产生的奖励点数）。经确认，真实模型为：

- 客户**自操作**（注册 / 开通虚拟账户 / 开卡 / 卡充值 / 币兑）→ 获得 **YASBee Points**（奖励点数，非代币本身）；
- 客户账户内另有**持有的 YASBee Cash 资产**（购买 / 空投赠送来源），与奖励点数**分属两类、分开展示**，不得混用同一余额口径；
- 代理维度：被代理人（下级客户）发生操作时，代理获得 **U（USDT/USDC） + YASBee Points**；U 返佣在代理管理/分销配置，YASBee Points 返佣在奖励规则设置页「代理返佣设置」卡片；
- 存在代理关系时，被代理人开卡享受**开卡优惠价**（原需求：实体卡 $200 零售 / 推荐 $150），优惠规则必须产品化并写入 PRD。

### 1.2 目标

1. 客户端 Rewards 页：**单张表 + 资产类型切换**（YASBee Cash / YASBee Points），切换控件位于页面标题行右侧，统辖统计条与表格；两类资产各自记忆页码；业务信息列只展示客观业务事实，不向客户展示规则说明/解释文字。
2. 管理端奖励配置**按维度拆分**：
   - **客户维度（YASBee Points 奖励）** → 分销管理下的**奖励记录与规则设置**页面（一页两级，记录列表为主视图、规则设置为下级页）；
   - **代理维度奖励**（返 U + YASBee Points）→ U 返佣保留在**原本返佣设置**（代理管理 / 分销配置体系）；YASBee Points 返佣在奖励规则设置页「代理返佣设置」卡片配置。
3. 业务场景覆盖：注册、开通虚拟账户、开卡、卡充值、币兑**五种**客户自操作场景发放 YASBee Points；其中币兑、注册、开通虚拟账户为新增场景（旧需求不含）。
4. 计奖口径统一：按美元折算的场景一律用**「每 XXX USD = N 点」**固定数形式配置（不使用百分比），奖励数量**保留小数点后一位，低于 0.1 的部分不计入（不四舍五入）**。
5. 规则与返佣账务可配置、可追溯；退款/逆向操作时奖励可自动追回（Clawback）。

### 1.3 范围

| 需求 | 包含 | 不包含（后续迭代） |
|------|------|--------------------|
| 客户端 Rewards | YASBee Cash 资产表、YASBee Points 奖励记录表、顶部类型切换、双 token pill、统计条现算 | 奖励资产交易/转账、Points 提现 |
| 客户维度奖励场景 | 注册 / 开通虚拟账户 / 开卡 / 卡充值 / 币兑 发放 YASBee Points | 其他业务类型（消费返现等） |
| 管理端拆分 | 客户维度奖励记录 + 规则设置（一页两级）；代理奖励在原返佣设置 | 分销多级（仅一级） |
| 开卡优惠 | 代理关系被代理人开卡优惠价 | 动态折扣活动体系 |
| 逆向 Clawback | 退款/逆向时追回已发 YASBee Points 与代理返佣 | 结算批次自动对账工具 |

## 2. 术语与命名

| 术语 | 含义 | 展示/口径约束 |
|------|------|---------------|
| **YASBee Cash** | 客户账户中的资产；来源为**购买**与**空投赠送** | 客户端顶部 pill「YASBee Cash / 持有」；表格类型 Cash，6 列；资产代码 `yasbee+` 展示于资产列名称旁 |
| **YASBee Points** | 客户自操作（注册 / 开通虚拟账户 / 开卡 / 卡充值 / 币兑）获得的**奖励点数**（旧需求「积分」的对应物） | 客户端顶部 pill「YASBee Points / 累计到账」；表格类型 Points，5 列；管理端配置单位写作 **yasbee points**；**禁止**以「积分」名义展示 |
| **U** | USDT/USDC，代理返佣的现金结算币 | 代理维度结算，客户端不展示 |
| 客户维度 | 客户本人操作（注册/开通虚拟账户/开卡/卡充值/币兑）→ 发 YASBee Points | 管理端：奖励规则设置（本页下级页） |
| 代理维度 | 被代理人（下级）操作 → 代理返 U + YASBee Points | 管理端：U 返佣在代理管理/分销配置；YASBee Points 返佣在奖励规则设置页 |
| 开卡优惠 | 存在代理关系时，被代理人开卡按优惠价计 | 入 PRD，管理端配置优惠价与原价 |
| Clawback | 逆向追回已发放的奖励/返佣 | 退款、销卡、订单作废时触发 |
| 计奖精度 | 奖励点数保留**小数点后一位**，低于 0.1 的部分不计入（不四舍五入） | 客户端与管理端展示均为 1 位小数（如 `413.0`） |

**命名纪律**：全站（客户端 + 管理端）奖励资产统一写作 **YASBee Points**（展示）/ **yasbee points**（配置单位），不使用 `yasbee+` / `yasbe+` 旧写法、不使用「积分」。

## 3. 业务模型总览

```
┌─ 客户维度（本 PRD 5.2 / 5.3；管理端一页两级）────────────────────────────┐
│  客户自操作          → YASBee Points（客户端 pill + Points 表，按业务类型区分）│
│    注册  ＋N yasbee points/客户 · 每客户限一次（终身）                         │
│    开虚拟账户  ＋N yasbee points/账户 · 按账户计，不区分币种                   │
│    开卡  ＋N yasbee points/张 · 实体卡/虚拟卡分两行（优惠价场景按实付计）      │
│    卡充值 每 XXX USD = N 点 · 单行配置，不区分卡种（实体卡与虚拟卡同规则）     │
│    币兑  每 XXX USD = N 点 · 与卡种无关（单行）                              │
│  计奖精度：保留小数点后一位，低于 0.1 的部分不计入（不四舍五入）              │
└───────────────────────────────────────────────────────────┬───────────┘
                                                             │
┌─ 代理维度（YASBee Points 返佣在奖励规则设置页；U 返佣在代理管理/分销配置）┐
│  被代理人操作       → 代理返 U + YASBee Points                     │
│    YASBee Points 返佣（下级开卡 / 充值 / 币兑 三类可配）      │
│    U 返佣：开卡（原 $100 档位）/ 充值（原 0.30% 比例）               │
│    开卡优惠：被代理人在代理链接下开卡按优惠价（原 $150 vs $200）      │
└─────────────────────────────────────────────────────────────┘
```

## 4. 需求来源与口径映射

原始需求（`实体卡 $200 / 推荐 $150 / 代理 $100 / 充值 0.30% / 积分`）作为**数字基准**，映射如下：

| # | 原始需求 | 旧模型 | 新模型（本 PRD） |
|---|----------|--------|------------------|
| 1a | 代理获得 $100 开卡费奖励（被推荐人开卡成功） | 代理现金 $100 | 代理维度返 U（$100 为演示基准），另按配置返 YASBee Points |
| 1b | 客户开卡费 $150（被推荐） | 客户价 $150 | **开卡优惠**：代理关系下被代理人开卡 $150，无代理关系 $200（可配） |
| 2 | 充值返现给代理 0.30% | 代理现金 0.30% | 代理维度返 U 0.30%（可配），另按配置返 YASBee Points |
| 3a | 客户开卡成功：代理 10 分、客户 10 分 | 积分 | **YASBee Points**：客户 +10.0 yasbee points/张；代理按代理维度配置返 |
| 3b | 客户每充值 $10：代理 0.2 分、客户 1 分 | 积分 | **YASBee Points**：客户每 10 USD 充值 = 1.0 yasbee points；代理按代理维度配置返 |
| 4 | （旧需求无币兑） | — | 新增**币兑发 YASBee Points** 场景，按「每 XXX USD = N 点」配置 |
| 5a | （旧需求无注册奖励） | — | 新增**注册发 YASBee Points** 场景，按「每客户固定 N 点、每客户限一次」配置 |
| 5b | （旧需求无开通虚拟账户奖励） | — | 新增**开通虚拟账户发 YASBee Points** 场景，按「每账户固定 N 点」配置 |
| 5 | 积分供应无上限，至小数点后 1 位 | 积分精度 | YASBee Points 精度：**保留小数点后一位，低于 0.1 的部分不计入（不四舍五入）** |

**功能点 F-203：卡种维度奖励配置（实体卡 / 虚拟卡）**

| 项 | 内容 |
|----|------|

## 6. 现有系统改造方案（客户端 / 管理端）

> 本章只写「从现行页面到目标态」的改造动作。**所有现状描述均取自本仓库原型实测**（`prototypes/返佣和奖励/`，2026-09-18 代理体系 4 页 + 2026-09-09/09-10 奖励本体 2 页 及管理端同级页面），不引用推测。改造动作分三类：**保持**（现状已满足）、**调整**（页面已有元素，改口径或改归属）、**新增**（现状不存在，需新建）。凡本文标注「待确认」者列入附录 B，不由本文拍板。

### 6.1 判定口径：代理身份 = 可见性开关

客户端一切与「返佣 / 代理」相关的元素，是否渲染**只由代理身份状态决定**，不由页面决定。身份状态取五值：

| 身份状态 | 判定条件 | 客户端可见面 |
|---|---|---|
| 普通用户 | 无代理关系，未发起申请 | 仅「代理计划」邀约入口（申请入口态） |
| 申请中 | 已进入签署流程但未完成签署 | 申请入口态 + 签署页访问权 |
| 核验未通过 | 系统自动核验未通过（管理端「自动核验未通过」） | 申请结果页失败态（含原因与重试引导） |
| 已开通代理 | 系统自动核验通过、代理编号已下发 | 代理中心全部数据面 |
| 已停用 | 管理端「已停用」 | 待确认（见附录 B #19） |

可见性三档，落地时按元素粒度取值：

- **可见**：正常渲染，参与布局
- **可见 · 只读存证**：页面可进，数据不可改（签署页在开通后转为存证调阅）
- **不可见**：**不渲染、不占位**，父级布局按剩余元素重排（不留灰化占位、不出「暂未开放」提示）

判定不得在前端硬编码，须由服务端随用户信息下发代理能力位（见 6.8）。

### 6.9 改造边界（本轮不做）

- 不做多级分销（仅一级推荐关系）

### 6.10 改造验收

1. 普通用户登录客户端，全站检索「代理 / 返佣 / 下级 / 返点」字样为 0 处（入口卡除外），DOM 中无灰化占位节点。
2. 普通用户在 Rewards 页可看到入口卡并进入申请入口态；直达签署页 / 结果页 URL 时被正确重定向。
3. 申请中用户：入口卡文案为申请中，签署页可进，其余代理数据面仍全部不可见。
4. 核验未通过用户：可见失败态与原因，可重新发起；数据面不可见。
5. 已开通代理：入口卡切「我的代理中心」，中心态 4 统计 / 推广链接 / 返佣记录 / 我的返佣比例全部可见，签署页仅可调阅存证。
6. 管理端将某代理置为「已停用」后，该用户客户端数据面即时不可见，管理端历史记录仍可查（回落文案按附录 B #19 结论执行）。
7. 管理端导航：全站不再出现指向 2026-07/08 旧口径页的入口；代理商-卡产品返佣来源在代理兜底值规则页与奖励页代理返佣设置两处一致、不冲突。
8. 客户端与代理中心同一用户的 Cash / Points 余额口径一致（F-307）。

### 8.1 存量数据迁移口径（上线迁移）

新体系上线时，现有系统中已存在的资产与点数数据按下表处理，**一律保留、不作废、不清零**。Cash 与 Points 分属两类资产（见 1.1 / 2），迁移过程**不得互相折算或合并**。

| 存量数据 | 说明 | 迁移口径 |
|----------|------|----------|
| YASBee Cash（客户**付费购入**） | 现有系统内客户已花钱购买获得的 Cash 资产 | **保留**：持有数量 / 单价 / 持有价值 / 锁仓信息 / 交易日期原样迁移，来源标记「购买」 |
| YASBee Cash（空投赠送） | 现有系统内已通过空投赠送获得的 Cash 资产 | **保留**：字段同上原样迁移，来源标记「空投赠送」 |
| 历史积分 / **point** 数据 | 现有系统中部分既有数据属旧口径积分（point） | **备注迁移**：迁入 YASBee Points 口径展示与统计，记录**须带来源备注**（标注为历史迁移数据），不与 Cash 合并 |

**口径注记**

- 两类 Cash 存量迁移后仍计入客户端 Rewards 页 Cash 表与统计条：按来源分别计入「累计购买」与「累计空投赠送」，当前持有按两者之和扣减已用部分的现算口径（见 F-101 统计条）。
- 历史 point 数据迁移后一律按 **YASBee Points** 展示与统计（命名纪律见 NFR-1）；迁移记录带来源备注，用于与「新体系发放」的奖励记录区分。
- 迁移时点（上线时一次性 / 分批）与迁移记录的编号口径（沿用原编号 / 按 `PT-YYMMDD-NNNN` 重编）由后端实现决定，待确认项见附录 B #11。
