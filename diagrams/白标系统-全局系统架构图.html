3 · 分层图例 层 = 图中色块（subgraph）；参与方与界面层已拆开，界面层 = 三个独立前端工程

L0 · 参与方 ACTOR

人与系统：租户系统（下游集成方：调我方 API + 接收 Webhook）、终端用户（租户自己的客户）、平台运营（我方运营与审核岗）。
终端客户没有我方界面，全部经租户系统间接使用；我方与终端客户无直接关系。

L0 · 界面层 UI

三个完全独立的前端工程：白标开发者门户（服务租户开发者）、租户业务台（服务租户业务人员）、平台运营总台（服务我方运营）。
前端与后端网关平行、不互为上下游；一期交付按这三个工程切分，工程量与接口互不耦合。

L1 接入层

本层 = 两个服务：统一 API 网关（鉴权、限流、幂等、签名、版本）+ 接入与准入服务（建档、分模块审核、签约、联调、切生产闸门）。
一期无沙盒：联调用受限 key（限额度 + 白名单收款人），接口仍是生产接口。

L2 平台服务层

本层 = 三个业务服务 + 公共尾部：法币 / 加密 / 卡片，公共尾部为账本、定价与费率、计费与结算、风控与合规、通知、审计。
三个业务服务互相独立、按模块分别放行，因此「部分生产」是常态。

L3 适配层

本层 = 适配器（Adapters）。每个上游一家一个适配器，把各家 API 的字段、状态、错误码、回调差异抹平， 对上只暴露统一接口，业务服务不感知具体上游。
换上游、加币种、加卡产品只改适配器，不动业务服务与租户集成。

L4 上游提供商层

能力兑现方保留 5 家，按一期 / 二期强隔离：
一期交付范围（图上实线高亮）：Bridge（USD）、OpenPayd（EUR / GBP · Linked Client）、SafeHeron（加密托管）、Interlace（卡片 BIN 与清算）。
二期（图上虚线）：BitGo（币兑）。二期只保留适配器接口位（ADP_FX），不纳入一期验收、不参与一期联调。
通道按币种路由（USD 走 Bridge，EUR / GBP 走 OpenPayd），租户侧无感；凭据不入文档。

领域实体

第 2 张图为主，实体不加层前缀：租户、密钥、模块准入、租户定价与费率、终端客户引用号、VA、托管地址、卡产品 / 持卡人 / 卡、 交易、账本分录、价格快照、风险筛查、结算单、对账文件、回调订阅与投递、审计日志。

4 · 缩写与业务含义 本图中出现的缩写、在本次 BaaS 业务里具体是什么、起什么作用

缩写 / 术语全称在本次 BaaS 业务中的含义与作用
BaaSBanking as a Service我方把银行账户、加密托管、发卡这些能力封装成 API 开放出去；租户拿去叠自己的产品与品牌，终端用户看不见我方。
白标 / White-label—下游用我方能力 + 自己的品牌对外提供服务。因此本系统里「客户」有两层：租户（集成方）与租户的终端客户。
租户 / Tenant—下游集成方（客户类型：同行平台，要底层能力、自己再叠一层产品）。一租户对应一个自有系统、一把访问密钥、一份档案。
KYBKnow Your Business企业主体审核（本业务只做 KYB，不做个人 KYC）。法币 / 加密 / 卡片三模块各自独立过 KYB，任一模块不通过不影响其它模块。
VAVirtual Account虚拟账户，法币收付的落点。每个终端客户、每个币种一个 VA；到账凭 VA 号自动归因到该终端客户，无需付款方填附言。
受限 keyRestricted API Key联调期密钥：额度受控（单笔与日累计上限）+ 收款人 / 地址白名单，接口仍是生产接口（一期无沙盒）。
生产 keyLive API Key过一个模块的切生产闸门，就解除该模块的额度限制。一租户一 key，模块授权写在租户档案里。
幂等键Idempotency Key同一键同一参数重复请求返回首次结果，防止重复开户、重复扣账、重复出金。
归因Attribution把一笔到账认到某个终端客户：法币凭 VA 号，加密凭地址。归因失败即未识别资金。
挂账—金额对不上或来源不明的入金，先挂起不记账，限期内处置，超时原路退回。
回冲Reversal出金失败 / 被退回时，把已扣资金按原路径退回终端客户账户，账本留对应分录。
拒结—加密入金来源地址风险命中且判定不予接收时，不入账、原路退回，并留风险记录。
确认数Confirmations链上充值所需区块确认门槛，未达标不入账，避免区块回滚造成的账实不符。
地址风险筛查Address Screening对加密来源 / 目标地址做风险打分，返回风险等级 0-5：0-2 自动通过，3-5 转人工复核。
适配层 / AdapterPorts and Adapters抹平上游 API 差异的一层。业务服务只面对统一接口，换上游 / 加币种 / 加卡产品只改适配器，不动业务服务与租户集成。
上游提供商Upstream Provider能力兑现方：Bridge / OpenPayd（法币）、SafeHeron（加密托管）、Interlace（卡片）、BitGo（币兑 · 二期）。凭据不入文档。
通道路由Channel Routing按币种选上游通道：USD 走 Bridge，EUR / GBP 走 OpenPayd。租户侧无感，不需要知道用了哪家。
BIN / 卡产品Bank Identification Number卡产品（卡种、币种、BIN）是平台级资产，挂在持卡人之下发给终端客户；对租户呈现为「可用卡种」。
实时授权 / 清算Authorization / Clearing刷卡两段式：授权毫秒级占额并实时回调，清算按实际金额入账。授权与清算各产生交易记录。
价格快照Price Snapshot记账与计费时落定价格，之后调价不追溯已发生交易，保证已出账单可复现。
结算单 / 对账Statement / Reconciliation周期账单（含用量与费用明细）+ 对账文件 / 对账结果。账单可下钻到原始交易；争议走线下处理。
部分生产—按模块分别过闸门带来的常态：例如法币已生产、卡片还在联调。租户可先用法币模块跑业务。
PIIPersonal Identifiable Information终端客户个人信息。我方不建终端客户主档（D4），只存外部引用号与上游必需的最小要素。
Webhook—我方把事件（到账、出金结果、卡授权、风险处置等）主动推给租户系统；失败重试，最终失败告警。
租户定价 / 费率Tenant Pricing每个下游租户单独配置的算钱口径（如法币入金 1% 或 1.5%、出金固定费、卡消费费率）。与租户一一对应，是账单与结算单的计费依据；改价不追溯已发生交易。
审计日志Audit Log独立留痕实体：谁（平台超管 / 租户管 / 系统）在什么时间、对什么对象（租户、模块准入、密钥、交易、定价配置）做了什么变更，含变更前后值与来源 IP。合规用途，不可删改。
